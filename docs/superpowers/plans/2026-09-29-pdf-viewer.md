# Просмотр PDF — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Вкладка-просмотрщик PDF «уровня markdown-ридера»: лента страниц fit-width, поиск, выделение/копирование, ссылки, тёмные страницы, поставка движка pdfium.

**Architecture:** Один фоновый поток владеет `Pdfium` и документами и общается с UI через `UiWaker`-канал (запросы/события, поколения для отмены). Страница — одна GL-текстура, растеризуется вне кадра, кэш только у активной вкладки. Библиотека `libpdfium` не вшивается: ищется рядом с exe / в data-dir / по переменной, ставится по кнопке через `tool_installer`; единый манифест `pdfium.json` для Rust и Python.

**Tech Stack:** Rust, `pdfium-render 0.9.4` (dynamic, `default-features = false`, `features = ["pdfium_latest"]`), `tar 0.4` + `flate2 1.1` + `sha2 0.11` (загрузка), `serde_json` (манифест), `regex` (поиск), glow (текстуры), Python 3 (`scripts/fetch_pdfium.py`).

**Spec:** `docs/superpowers/specs/2026-09-29-pdf-viewer-design.md` — план аргументирует от спеки; исполнитель читает оба документа. Номера `§` ниже — разделы спеки.

**Карточка Kanri:** `vn2frxr48wa5inpi7lanrhuc` («добавить поддержку pdf», Features).

## Global Constraints

- `pdfium-render = { version = "0.9.4", default-features = false, features = ["pdfium_latest"] }` — без `static`, без `thread_safe`; `use pdfium_render` только в `src/pdf/pdfium_backend.rs` (§3).
- Ни один вызов pdfium в UI-потоке; в draw-path только bind + quad, ≤ 2 `upload_rgba` за кадр, никаких `format!` кроме подписи плейсхолдера и статус-бара, никакого I/O (§12).
- Все координаты выше backend'а — pt с origin в верхнем левом углу страницы; Y-переворот только в backend'е (§4.2).
- Размер растра: `width_px = min(page_w, 4096, floor(4096·w_pt/h_pt))`, `height_px = round(width_px·h_pt/w_pt)` (§6.2).
- Текстуры и `pending_bitmaps` только у активной PDF-вкладки; единственный владелец освобождения — `App.pdf_textures_to_free`, дренаж в начале каждого кадра (§6.3).
- На каждый `Render` ровно одно из `Page`/`RenderSkipped`, на каждый `PageText` — `Text`/`TextFailed` (кроме `closed`) (§4.1).
- Перезапуска движка нет: после `EngineFailed` — состояние `Failed` до перезапуска приложения (§4.3). **Отклонение от §4.3:** `catch_unwind` не работает — в проекте `panic = "abort"` (`Cargo.toml:213`, `Makefile:13,56,98`), паника в воркере завершает процесс, как и segfault нативного кода (спека это уже принимает). `EngineFailed` шлётся только при неудачном `bind`; `Disconnected` канала трактуется как `EngineFailed("поток движка завершился")`.
- Коммиты внутри задач (шаги «Коммит») делает тот, кому велит SDD-скилл (implementer в своей задаче); строка AGENTS §3 «subagents never commit» — правило вне Superpowers, как и §4 про тесты.
- Загрузка библиотеки только по кнопке, без автоповторов; SHA-256 против манифеста, из архива берётся только запись `lib`; в `cfg(test)` установка — no-op с фазой ошибки «отключено в тестах» (§8.3, §10.3-7).
- `RRITER_PDFIUM_PATH` задана → только она, без фолбэка (§8.2). Сеть в тестах не используется; библиотеку тестам даёт `make codex_test`/`make test` через `RRITER_PDFIUM_PATH` (§8.4).
- Все UI-строки — по-русски, как в проекте («стр. N / M», «Загрузить PDF-движок (3,7 МБ)», «Отмена», «Повторить»).
- Лимиты файлов: мягкий 1500, жёсткий 1600 строк; `main_keys.rs` = 1600 — в него только вызов; новый файл ≥ 200 строк (исключение — `src/pdf/fixture.rs`, `cfg(test)`, ~150 строк, разрешено планом); каждый новый файл — в `PROJECT_GUIDE.md` §4.
- Без runtime `unwrap`/`expect` в production-путях; без новых `static` с данными; без `#[allow]`; без `rustfmt`.
- Правило «поля меняются одним методом»: `PdfTabState::apply_event` — единственное место, меняющее `phase`, `pages`, `text`, `search.matches`; `set_viewport` — единственное место пересчёта `layout`; кламп скролла — один helper `PdfTabState::clamp_scroll()`, который зовут `set_viewport`, `scroll_by`, `scroll_to_page` и автопрокрутка drag (§5.2, уточнение плана).
- Рендерер получает вкладки как `&[EditorTab]` (`root_frame_renderer.rs:128`): всё, что меняет `PdfTabState` или шлёт запросы (`set_viewport`, `take_*_requests`, загрузка текстур, `retain`, `pdf_textures_to_free`), делается в `App::pdf_prepare_frame(&mut self, renderer: &mut Renderer)` из `main_frame.rs` **до** `renderer.draw` (:127); `draw_root_pdf_frame` читает `&PdfTabState`.
- `EditorTab` без derive (`app_state.rs:37`), `EditorTabKind` требует `Eq, Clone` (:89) — состояние PDF хранится в `EditorTab.pdf: Option<Box<PdfTabState>>`, вариант `EditorTabKind::Pdf` без данных; все 22 литерала `EditorTab {` получают `pdf: None`.
- `app_ide_tab_methods.rs` = 1585 строк: в него только однострочные вызовы, тела хуков — в `src/app/pdf_tab/engine.rs`.
- Клавиши: `handle_pdf_key` поглощает всё без Ctrl/Alt/Super (иначе скрытый редактор получит ввод и пометит вкладку изменённой — `main_keys.rs:863`), пропускает сочетания с Ctrl (Ctrl+F, Ctrl+W, Ctrl+Tab остаются общими), кроме Ctrl+C (Task 6).
- `pdfium.json` в корне — именованное исключение из AGENTS §3 (Task 1 вписывает его в AGENTS.md).
- Бинарных fixture в репозитории нет; PDF для тестов генерируется кодом (§10.2).
- Тесты идут параллельно в отдельных процессах: всё вне процесса — per-PID (`std::process::id()`), env в тестовом процессе выставлять можно.

## Review Focus

Классы входов, которые спека подразумевает, но ни один сценарий §10.3 не проверяет; тест на каждый — в задаче-владельце.

1. **Страница с нулевой шириной/высотой или экстремальным соотношением сторон** (`w_pt = 0`, лента 1×10000 pt): раскладка не делит на ноль, растр не превышает 4096 по обеим сторонам, `Render` с `width_px = 0` не отправляется. → Task 5, unit-тест `raster_size`/`PdfLayout`.
2. **Файл `.pdf` нулевой длины и каталог с расширением `.pdf`**: `Error(...)` в теле вкладки, приложение живо, без паники в `open`. → Task 3 (`open` на пустом файле → `Invalid`), Task 4 (headless: пустой файл → `phase = Error`).
3. **Текст страницы без единого символа (скан) при поиске/выделении/Ctrl+C**: `SearchPage` не приходит, `SearchDone` приходит; drag ничего не выделяет (`selection_chars = 0`); Ctrl+C не пишет в буфер. → Task 6, headless-сценарий на стр. без текста (fixture получает третью пустую страницу, §10.2 расширяется).
4. **Регулярное выражение из панели с ошибкой синтаксиса или пустое совпадение (`a*`)**: поиск не запускается на невалидном паттерне (как в редакторе), паттерн с пустыми совпадениями не зацикливает воркер и не даёт нулевых диапазонов. → Task 3 (unit: `search_page` с `a*` завершается, пустые совпадения выброшены), Task 6 (`update_search` с `(` → `matches` пуст, `done = true`).
5. **Ссылка GoTo на страницу вне диапазона и URI не-http (`mailto:`, `javascript:`)**: backend отбрасывает URI не `http(s)`, `Page { page ≥ count }` клампится при переходе, а не паникует. → Task 3 (unit на fixture с `mailto:` и GoTo на стр. 99), Task 6 (клик → `current_page` = последняя).
