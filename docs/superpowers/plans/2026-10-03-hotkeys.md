# Переназначаемые горячие клавиши — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** команды приложения получают переназначаемые сочетания (вкладка Settings «Горячие клавиши» и `config.json`), умолчания остаются прежними, плюс 24 новые команды без умолчаний.

**Architecture:** модуль `src/keymap.rs` (+ `src/keymap/defaults.rs`) без зависимости от `App` — команды, сочетания, разбор, `Keymap`. Ветки диспатча остаются на месте и в том же порядке, меняется только проверка клавиши (`self.keymap.hit(Command::X, chord)`); фиксированные ветки и фильтры безопасности переводятся на `is_reserved` и команды; новые команды — `App::run_command`. Пользовательские данные — `KeymapOverrides` в `Config`, одна точка фиксации `App::set_keymap_overrides`.

**Tech Stack:** Rust (nightly, `make test TEST_FILTER=…`), winit `KeyCode`/`ModifiersState`, `serde_json`, headless-драйвер `python3 scripts/rriter_headless.py` и headless-тесты `src/headless/ui_tests_*.rs`.

**Spec:** `docs/superpowers/specs/2026-10-03-hotkeys-design.md` (§-ссылки ниже — на неё; исполнитель читает спеку вместе с задачей). Разведка текущего кода (не в git, читать по абсолютному пути): `/home/reyan/projects/rriter/.claude/recon/hotkeys-table.md` (таблица мест диспатча), `hotkeys.md` (представление клавиш, AltGr, headless-покрытие), `hotkeys-commands.md` (кандидаты C1–C24).

## Global Constraints

* Сочетания по умолчанию не меняются (§1, §8.2), кроме нестрогих вариантов (§3.3): нестрогий вариант, покрытый тестом или документацией, становится явным умолчанием.
* Модификаторы сравниваются точно — у команд и у фиксированных веток (§3.3, §3.4); фиксированные ветки проверяют модификаторы через `is_reserved`, так что `RESERVED` и ветки не расходятся.
* Ветки диспатча остаются в том же порядке и с теми же условиями контекста (§3.2); guard-only ветки в `match physical_key` — до `_`-ветки (R2).
* `hit` не аллоцирует и не хеширует; `Chord` вычисляется один раз на нажатие; в кадре нет `format!`/аллокаций для подписей — готовые строки пересобираются только в `set_keymap_overrides` (§2.4, §6).
* `App.keymap` и `App.keymap_overrides` меняются только через `App::set_keymap_overrides` (§2.4).
* Пропущенные записи конфига сохраняются нетронутыми; записи с неизвестным id UI не трогает никогда (§7).
* Терминал в фокусе забирает `terminal_intercepts(chord)` ранним шлюзом до всех веток команд (§3.5).
* Фильтры безопасности по клавишам (PDF/изображение) — на командах, не на `KeyCode` (§3.6).
* Текст UI — русский; id команд — английские, стабильные (`editor.save`, `git.push`).
* AGENTS.md: без `.unwrap()`/`.expect()` в продакшн-путях, без `#[allow]`, без rustfmt, файлы ≤1500 строк (жёсткий предел 1600 — `main_keys.rs` 1390, `editor_keys.rs` 1364, `keyboard.rs` 1437, `settings_ui.rs` 1520 уже близко: растущий файл выносит тронутый блок в свой файл), новые UI-элементы — через `UiId`, текст по округлённым базовым линиям, новые файлы — в `PROJECT_GUIDE.md` §4. Тесты параллельны и per-process: всё вне процесса — с `std::process::id()`.

## Review Focus

* RF-5 (Task 7): PDF-вкладка и команда, переназначенная на сочетание фиксированной навигации PDF (стрелки недопустимы — `Reserved`), и `Save`, вручную поставленная на то же сочетание, что `Find`, — ожидание: фильтр PDF блокирует (сочетание общее с `Save`), документ не перезаписывается; тест — unit фильтра в Task 7.
