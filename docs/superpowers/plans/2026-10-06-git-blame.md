# Git blame Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Inline git blame on the cursor line with a commit popup, a per-tab blame column in the gutter, and jump-to-commit in the git graph.

**Architecture:** One HEAD snapshot `(repo, head oid, path in HEAD, baseline text)` per editor feeds both gutter diff markers and blame; blame runs once per snapshot key (`git blame --porcelain <oid> -- <path>`) in the background, and buffer lines map to HEAD lines through the existing `Editor::git_hunks`. Pure data and algorithms live in `src/editor/git_blame_state.rs`; App wiring in `src/app/git_blame.rs`.

**Tech Stack:** Rust, git2 (libgit2), git CLI through `src/app/git_panel/git_process.rs`, custom GPU renderer, headless test driver (`src/headless/`).

**Spec:** `docs/superpowers/specs/2026-10-06-git-blame-design.md` — read it in full before starting any task; section names below refer to it.

## Review Focus

1. HEAD moves outside the app (commit/checkout in the terminal) while a file is open: after focus returns, annotations must belong to the new HEAD, never to shifted lines of the old one. Test in Task 1 (focus trigger) and Task 4 (annotation after external commit).
2. File encodings and line endings (CRLF, BOM, UTF-16, no final newline): HEAD-line count of the blame result must equal the baseline line count used by `git_hunks`; on mismatch blame is treated as unavailable, not misattributed. Test in Task 3.
3. Large files (20k lines): blame request does not block the UI thread, the frame does no work proportional to file size, git timeout yields "no blame" without retries. Test in Task 3 (non-blocking + single attempt) and Task 2 (`head_line_for` with thousands of hunks).
4. Non-ASCII and very long author names / summaries: truncation to width never splits a UTF-8 char and never panics. Test in Task 2 (formatting helpers) and Task 8 (column label).
5. Fast tab switching and cursor movement: a late blame response or message lookup is never applied to another tab; annotation never shows for a line it was not computed for. Test in Task 3 (stale response) and Task 4 (tab switch on same line number).

### Task 2: Blame data core

**Агенты:** implementer ds-low · reviewer ds-high — high: every later task consumes these types and the line mapping; a wrong offset misattributes lines silently.

**Files:**
- Modify: `src/editor/git_blame_state.rs` (from Task 1), `src/editor/mod.rs` or equivalent module list, `PROJECT_GUIDE.md` §4.
- Test: unit tests in the same file (or `src/editor/git_blame_state_tests.rs` if the file would pass ~800 lines).

What to build (spec «Источник blame», «Сопоставление строк», «Состояние», «Формат»):
- `parse_porcelain`: `git blame --porcelain` format — header line `<40-hex oid> <orig_line> <final_line> [<group_count>]`, then key/value lines (`author`, `author-mail`, `author-time`, `author-tz`, `summary`, `boundary`, `filename`, …) only the first time an oid appears, then a `\t`-prefixed content line. Build `commits` (dedup by oid) and `line_commit[final_line-1]`. Zero oid (`0000…`) is kept as a commit flagged uncommitted. Any malformed header, missing content line, or final_line gap → `None` (no panic).
- `head_line_for`: hunks are sorted by `after_start`; binary search; line inside `after_start..after_end` → `None`; otherwise `line - Σ(after_len - before_len)` of hunks fully above. Lines past the end → `None`.
- `blame_blocks`: given HEAD-line → commit index for a run of buffer lines, mark which buffer lines start a block (first line, or commit differs from previous mapped line, or previous line unmapped).
- `age_rank`: per commit, rank of `author_time` among the file's commits normalized to `0.0..=1.0` (newest 1.0); computed once per `GitBlame`.
- No relative-date function here: the App side formats it with the existing `format_git_relative_time` (Global Constraints).
- `column_label(commit)`: `dd.mm.yy <author>` precomputed into `GitBlame` once, at most 24 chars (author truncated with `truncate_to_width`).
- `truncate_to_width`: truncate a string to N chars on a char boundary with `…`.
- `GitBlameState` type: `key: Option<(PathKey repo, PathBuf rel, Oid)>`, `generation: u64`, `blame: Option<GitBlame>`, `pending: bool`, `failed_key`, `messages: Vec<(oid, String)>` small cache, `column_open: bool`, plus the inline-annotation buffer fields Task 4 needs (`inline_text: String`, `inline_line: Option<usize>`) — keep them plain data; no App or renderer imports.

Tests (unit): porcelain with 2 commits, repeated commit without headers, `boundary`, zero oid, malformed line, empty output (empty file → `Some` with 0 lines, not `None`), non-ASCII author; `head_line_for` for insert, delete, delete at file start/end, replace, several hunks, line inside hunk, last empty line, empty hunks list, 5000 hunks (Review Focus 3); blocks; age rank with equal times; column label length cap; truncate with multibyte chars (Review Focus 4).

Steps: tests first → `make check-tests` → implement → `make test TEST_FILTER=editor::git_blame_state` → commit.
