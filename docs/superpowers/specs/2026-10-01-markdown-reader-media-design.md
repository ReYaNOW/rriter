## 2. Ключевые решения

### 2.1 Размер неизвестен до загрузки — заглушка и пересчёт (O1)

Вёрстка никогда не ждёт диска и сети. Пока результата нет, медиа-элемент — рамка с alt-текстом высотой в одну строку текста (`line_h`) плюс вертикальные отступы. Фоновая задача возвращает сразу натуральный размер и пиксели (одна стадия, без промежуточного «размер известен»: `OneShot` отдаёт один результат, `src/ui_waker.rs:176`). Появление результата с новым натуральным размером поднимает поколение медиа `media_gen`, раскладка пересчитывается не чаще раза за кадр, прокрутка привязана к верхнему видимому блоку (§5.4). Отвергнуто: синхронное чтение заголовка при вёрстке (дисковый I/O в кадре) и фиксированная высота блока (искажённые пропорции).

### 2.2 Один медиа-кэш на приложение

`MarkdownMedia` — собственный тип состояния (правило AGENTS.md: логика фичи в своём типе, `impl App` только маршрутизирует), поле `App`, общее для всех вкладок. Ключ `MediaKey`:

- `File(PathKey)` — локальный файл;
- `Url(String)` — `http(s)`;
- `Mermaid(u64)` — хеш исходника блока.

Запись: натуральный размер (`natural_w`, `natural_h`, в пикселях источника или единицах SVG), состояние `Pending` / `Ready` / `Failed(MediaError)`, а при `Ready` — GPU-текстура и её растровый размер. CPU-пиксели живут только от конца задачи до загрузки на GPU и сразу освобождаются. Натуральные размеры и `Failed` хранятся до инвалидации (§4.4), текстуры — в бюджете (§4.3).

### 2.3 Всё декодирование — в дочернем процессе-хелпере

В release `panic = "abort"` (`Cargo.toml:215`) и он остаётся (решение 01.10): паника декодера или mmdr в потоке завершила бы редактор вместе с несохранёнными вкладками. Поэтому **всё** декодирование — растр (`image`), SVG (`usvg`/`resvg`) и Mermaid (mmdr → SVG → `resvg`) — выполняет дочерний процесс того же исполняемого файла со скрытым флагом `--rriter-media-render` (по образцу `--rriter-elevated-save`, `src/platform/elevated_save.rs:23`; ранний выход в `main` до любой инициализации). В процессе редактора остаются только чтение файла и сеть.

- Один запуск — один элемент: запрос (вид входа, параметры размера, байты) на stdin, ответ (натуральный размер, растровый размер, RGBA8) или текст ошибки на stdout; таймаут 10 с; запуск через `platform::ManagedChild` / `run_command_output` (`src/platform/process.rs:649`), процесс в группе процессов редактора. Одновременно живёт не больше хелперов, чем слотов задач (3); в простое хелперов нет.
- Паника (в release — abort), таймаут, нехватка памяти, ненулевой код — `Failed` этого элемента; редактор не затронут. Для Mermaid блок остаётся кодом, как сейчас, с одной строкой ошибки под шапкой.
- Шрифты для текста в SVG и в Mermaid хелпер берёт только из шрифтов редактора, без сканирования системных, чтобы запуск стоил единицы миллисекунд. Если mmdr без сканирования системных шрифтов не работает и запуск выходит дорогим (> 50 мс на элемент), вместо одноразовых запусков — один долгоживущий хелпер на слот, который завершается после 60 с простоя; упавший хелпер отдаёт `Failed` текущему элементу, следующий элемент запускает новый (без повторов упавшего). Выбор фиксирует план замером.
- В тестовом бинарнике `current_exe` — не rriter, поэтому у вызова хелпера есть режим «в процессе» только для `cfg(test)`.

`mermaid-rs-renderer` — с `default-features = false` (без CLI и PNG-бэкенда). Тема тёмная, под фон редактора: встроенный тёмный пресет mmdr, если он есть; иначе стандартная тема на светлой скруглённой подложке (выбор фиксирует план после проверки API mmdr).

### 2.4 Зависимости

- `mermaid-rs-renderer` (новый crate, согласован).
- `image`: фичи `jpeg`, `gif`, `webp` в дополнение к `png` (согласовано).
- `usvg`/`resvg`: фича текста, если её нет, — без неё текст в SVG-бейджах не рисуется. База шрифтов (`fontdb`) наполняется шрифтами редактора внутри хелпера.

## 4. Медиа-кэш и загрузка

### 4.1 Кто и когда запрашивает

Запросы идут со стороны App, не из рендера: после `refresh_read_model` (новая версия документа) App собирает из `MarkdownDocument` медиа-ссылки (картинки абзацев из одних картинок и блоки mermaid) и отдаёт их `MarkdownMedia::request(key, max_raster_w)`, где `max_raster_w` — ширина колонки текста в пикселях. Ключ уже в полёте, `Ready` или `Failed` не перезапрашивается (дедупликация по ключу). Рендер только читает состояние.

### 4.2 Фоновые задачи

Через `UiWaker::spawn_one_shot` (`src/ui_waker.rs:138`); одновременно не больше 3 слотов, остальные запросы — в FIFO-очереди в порядке документа, видимые ключи вперёд. Слот освобождается, только когда результат загружен на GPU или отброшен, поэтому очередь готовых пикселей не больше 3 штук. Задача:

- **файл**: `std::fs` чтение байтов (файл больше 20 МБ — ошибка без чтения);
- **http**: клиент из `platform::blocking_http_client_builder` с таймаутом 15 с; ответ больше 20 МБ (по `Content-Length` или по факту чтения) — ошибка; успешный ответ пишется в дисковый кэш `platform::cache_dir()/markdown-images/<hex u64 хеша URL>`, повторный запрос того же URL читает оттуда;
- затем байты (или исходник Mermaid) уходят хелперу (§2.3), который возвращает RGBA. SVG определяется по расширению, `Content-Type` или сигнатуре; внешние ресурсы SVG (`<image href>`, внешние стили) не загружаются никогда: и для http, и для локальных.

Растровый размер результата: натуральный × масштаб UI, уменьшенный до `max_raster_w`, длинная сторона ≤ 4096 px. Ограничения входа в хелпере: `image::Limits` с `max_alloc` 128 МБ и длинной стороной ≤ 16384 px — иначе `Failed(«слишком большая»)` до полного декодирования. Пиковая память редактора на задачи: входные байты ≤ 3 × 20 МБ плюс результаты ≤ 3 × 64 МБ; декодирование расходует память хелпера, не редактора.

### 4.3 Кадр и бюджет текстур

Порядок в кадре, до отрисовки markdown:

1. `MarkdownMedia::poll()` — результаты готовых задач; новый натуральный размер поднимает `media_gen`.
2. Раскладка активной вкладки (`prepare_markdown_read_layout`, `src/render_view/markdown_read.rs:899`) получает на чтение `&MarkdownMedia` (натуральные размеры и состояния по ключу); при смене `media_gen` пересчитывается и применяет привязку прокрутки (§5.4).
3. App берёт видимые ключи из видимого диапазона новой раскладки.
4. `MarkdownMedia::prepare_gpu(renderer, visible)`: загрузка не больше двух текстур за кадр (видимые вперёд); запрос повторного рендера для видимых без текстуры; вытеснение.
5. Если остались незагруженные результаты или задачи в полёте с видимыми ключами — запрос следующего кадра (задачи сами будят UI через `UiWaker`).

Бюджет текстур 128 МБ (w × h × 4). Сверх бюджета вытесняются невидимые текстуры по давности показа; видимые не вытесняются никогда, даже если одни они больше бюджета, — поэтому вытеснение не может зациклить повторный рендер. Вытесненный ключ сохраняет натуральный размер (раскладка не прыгает) и при возвращении в видимую зону рендерится заново, пока рисуется заглушка того же размера.

Перерисовка под новый размер: если растровый размер текстуры отличается от текущего отображаемого больше чем на 25% (смена масштаба UI или ширины колонки), ставится повторный рендер ключа под новый размер; до его готовности старая текстура рисуется масштабированной.

### 4.4 Инвалидация

- Событие файлового вотчера рабочей области по пути `File`-ключа сбрасывает запись (текстура освобождается, ключ перезапрашивается при следующей раскладке). Файлы вне рабочей области не отслеживаются.
- Открытие `.md`-вкладки заново сбрасывает записи `Failed` её ключей (повтор после ошибки — переоткрытием); `Ready` и натуральные размеры остаются.
- Дисковый кэш: фоновая задача обрезает каталог до 200 МБ (самые старые файлы) при первой записи за сессию и после каждых 50 МБ записанного.

## 5. Вёрстка и отрисовка

### 5.1 Какие картинки — блоки

Абзац, в котором кроме картинок только пробелы, переводы строк и ссылки, обёрнутые вокруг картинок (бейджи `[![alt](img)](url)`), становится медиа-блоком. Картинки в нём идут в ряд слева направо с промежутком `(8.0 * s).round()`; не помещается — перенос на новую строку ряда; высота строки ряда — по самой высокой картинке. Картинка внутри текста остаётся текстовой меткой, как сейчас, но кликабельна, если обёрнута ссылкой. Блок ```mermaid — медиа-блок из одного элемента.

### 5.2 Размер элемента

Отображаемый размер: натуральный × масштаб UI; если шире колонки текста — пропорционально уменьшается до её ширины; увеличения нет. Текстура рисуется в этот прямоугольник независимо от своего растрового размера (§4.3). Координаты и размеры округляются до целых пикселей.

### 5.3 Отрисовка

`draw_texture_quad` для записи с текстурой; скруглённая рамка с alt-текстом для `Pending` и для вытесненных; рамка с alt-текстом и причиной (`не найдено`, `HTTP 404`, `таймаут`, `больше 20 МБ`, `слишком большая`, `не удалось декодировать`, `не поддерживается`) для `Failed`. Рисуются только блоки в видимом диапазоне.

### 5.4 Пересчёт вёрстки и прокрутка

`LayoutKey` получает `media_gen`. Перед пересчётом запоминается верхний видимый блок (`source_range`) и смещение экрана внутри него; после пересчёта вычисляется дельта его новой позиции (`source_target_y`) и применяется через `ScrollState::rebase_current_preserving_target` (`src/scroll.rs:244`): текущая позиция и цель анимации сдвигаются на одну дельту, скорость сохраняется — идущая анимация колеса, переход к якорю или поиску продолжается к тому же месту текста. `jump_to` для этого не используется: он сбрасывает движение (`src/scroll.rs:269`). Если активен переход Read/Edit (`src/app/markdown_scroll_transition.rs`), его цель по `source_range` пересчитывается им самим, поэтому геометрия перехода берёт раскладку с текущим `media_gen`. Сценарий «картинка догрузилась во время анимации и во время перехода Read/Edit» — отдельный тест (§9).

## 6. Ссылки

### 6.1 Модель

При вёрстке каждый `StyledRun` ссылки получает индекс в `Vec<LinkTarget>` раскладки. `LinkTarget` разрешается из `destination_range` исходника: `External(url)` (`http`, `https`, `mailto`), `Anchor(slug)`, `File { path, anchor: Option<slug> }`, `Unsupported`. Путь и фрагмент декодируются из percent-encoding; путь разрешается от папки документа. Reference-ссылки и картинки (`[text][ref]`, `![alt][ref]`) разрешаются через определения `[ref]: url` документа (метки сравниваются без учёта регистра и с сжатием пробелов).

### 6.2 Slug'и

Как у GitHub: нижний регистр; буквы (включая кириллицу), цифры, `-` и `_` сохраняются; пробелы → `-`; прочее удаляется; повтор slug'а получает `-1`, `-2`… в порядке документа. Если заголовок сам даёт slug, совпадающий с уже выданным суффиксным (`foo-1`), побеждает первый в документе — как у GitHub.

### 6.3 Взаимодействие

Над ссылкой в Read-режиме — курсор-рука и подсказка с адресом (на механизме hover-подсказок). Клик — нажатие и отпускание на той же ссылке без перетаскивания; перетаскивание по-прежнему выделяет текст. Действие:

- `External` — `platform::open_url` (сейчас он принимает только `http(s)`; `mailto` добавляется в него же);
- `Anchor` — `animate_to` к заголовку со slug'ом; нет такого заголовка — ничего;
- `File` с `.md` — `open_file_in_tab`, режим Read, затем прокрутка к якорю, когда раскладка новой вкладки готова (ожидающий якорь в `MarkdownTabState`); прочие файлы — `open_file_in_tab` в обычном режиме; нет файла — сообщение об ошибке, как при открытии отсутствующего файла;
- `Unsupported` — ничего.

## 7. Оглавление

Заголовки (уровень, текст, `source_range`) берутся из `MarkdownDocument`. В Edit модель документа не обновляется сама (`refresh_markdown_read_model_if_stale` вызывается при переходе в Read, `src/app/markdown.rs:490`), поэтому открытие попапа сначала вызывает тот же refresh, если модель устарела (разбор инкрементальный).

Попап открывается кнопкой рядом с `MarkdownModeToggle` и сочетанием `Ctrl+Shift+O` (на macOS `Cmd+Shift+O` — основной модификатор приложения), в Read и в Edit. Сейчас его перехватывает ветка `KeyO if ctrl` (`src/app/keyboard/editor_keys.rs:776`), поэтому проверка сочетания оглавления ставится до неё, только для markdown-вкладок; в остальных вкладках поведение не меняется.

Строки — текст заголовка с отступом по уровню, длинные обрезаются многоточием; список длиннее экрана прокручивается колесом с общим виджетом скроллбара. Клавиатура в открытом попапе: `↑`/`↓` — выбор, `Enter` — переход, `Escape` — закрыть; клик вне попапа закрывает его. Переход: в Read — `animate_to` к заголовку, в Edit — к строке заголовка в редакторе. Основа — `draw_animated_context_menu` (`src/render_view/ide_panels/ide_panel_dialog_renderer.rs:950`), если он поддерживает прокрутку, иначе новый список на тех же примитивах рядом с ним.

## 8. Производительность

- В кадре нет дискового и сетевого I/O; декодирование, растеризация и mmdr — только в фоне.
- Не больше двух загрузок текстур за кадр; CPU-пиксели освобождаются сразу после загрузки.
- Пересчёт раскладки — только по смене `media_gen`, версии, ширины, масштаба или шрифта.
- Память: текстуры ≤ 128 МБ сверх видимых, задачи — §4.2.

## 9. Тесты

Юнит:
- slug'и: кириллица, пунктуация, повторы, коллизия с суффиксным slug'ом;
- разрешение `LinkTarget`: все виды, percent-encoding пути и фрагмента, `file.md#якорь`, reference-ссылки;
- распознавание абзаца из одних картинок (с бейджами-ссылками; абзац с текстом — не медиа-блок);
- вёрстка медиа-блоков с заданными размерами: уменьшение до ширины колонки, перенос ряда бейджей, округление;
- привязка прокрутки при смене `media_gen`: в покое, во время анимации колеса (цель сохраняется относительно текста), во время перехода Read/Edit;
- бюджет текстур: видимые не вытесняются сверх бюджета, вытесненный ключ перезапрашивается один раз, дедупликация задач;
