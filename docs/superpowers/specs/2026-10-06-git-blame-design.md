# Git blame — design

Kanri: `i1tnsphv` (Features). Backlog: `docs/feature-backlog.md:60` — «**Blame** — inline под курсором + колонка в gutter».

## Цель

Показывать, кто и когда последним менял строку, не уходя из редактора: inline-аннотация на строке курсора, попап с подробностями коммита, колонка blame в gutter по запросу и переход к коммиту в git-графе. Паритет с Zed (`git.inline_blame`) и IDEA «Annotate with Git Blame».

## Решения пользователя (06.10)

1. Переключатель inline blame — во вкладке Git, сохраняется между перезапусками.
2. Включён — на строке курсора после небольшой задержки показывается inline-аннотация; в статус-баре индикатор `Blame`, клик по нему выключает режим.
3. Задержка по умолчанию 400 мс, меняется в настройках.
4. Inline — одна аннотация только на строке курсора, не на каждой строке и не блоками.
5. Строки, изменённые относительно HEAD (не закоммиченные), аннотации не получают совсем — ни inline, ни подписи в колонке.
6. Длинная строка, после которой аннотация не помещается в видимую ширину, — аннотация не показывается (не обрезается).
7. Колонка blame в gutter включается и выключается правым кликом по номерам строк (меню из одного пункта), на конкретный таб, не сохраняется. Подряд идущие строки одного коммита подписываются один раз (на первой строке блока), далее полоса цвета возраста.
8. Попап по наведению на inline-аннотацию или на подпись в колонке.
9. Левый клик по подписи в колонке и кнопка «Показать в графе» в попапе открывают git-граф, прокручивают к коммиту и подсвечивают его строку. Коммит не найден за 5000 коммитов истории — сообщение в статус-баре, дальше не грузим.
10. Всё новое UI-взаимодействие покрыто headless-тестами.
11. Объём — пункты 1–3 одной спекой и планом, два PR: (A) снимок HEAD + inline + попап + переключатель + статус-бар + настройка + переход в граф; (B) колонка в gutter.

## Формат

- Inline: `<автор>, <относительная дата> • <summary>`, например `Ivan Petrov, 3 days ago • Fix scroll jitter`. Приглушённый цвет темы (роль, которой рисуются комментарии), отступ от конца строки; при soft wrap — после последнего визуального сегмента физической строки.
- Попап: полный хэш (копируется), автор и email, абсолютная дата, полное сообщение коммита (до загрузки — summary); действия «Копировать хэш», «Показать в графе».
- Колонка: `dd.mm.yy <автор>` (автор обрезается по ширине колонки), полоса возраста у левого края колонки: свежие коммиты ярче, старые бледнее (линейно по рангу даты коммита среди коммитов файла).
- Язык подписей — как остальной UI.

## Архитектура

### Снимок HEAD (общий контракт baseline и blame)

Сейчас `read_head_blob`/`load_head_text_for_worktree_path` (`src/app/git_diff.rs:371-403`) возвращают только текст, oid теряется; отсутствующий HEAD или путь превращаются в `Some("")`; baseline загружается синхронно и только при открытии файла, save-as и догрузке таба (`git_diff.rs:568`, `app_window_external_methods.rs:815,1148`, `app_ide_startup_methods.rs:420,465`).

- Загрузка baseline возвращает снимок `GitHeadSnapshot { repo_root (PathKey), head_oid: Option<Oid>, path_in_head: bool, text }`, из одного `repo.head()` → commit oid → tree. `head_oid == None` (unborn HEAD) или `path_in_head == false` (untracked, незакоммиченное переименование) — blame недоступен, аннотаций нет; baseline для gutter-маркеров ведёт себя как сейчас.
- Снимок хранится рядом с `git_base_text` в `Editor` (поля активного таба меняются местами целиком, `app_ide_tab_methods.rs:470`, поэтому baseline, hunks и blame переезжают вместе). `set_text_preserve_history` сохраняет снимок и blame так же, как сейчас сохраняет `git_base_text` (`editor_core.rs:904,923`).
- Внешняя перезагрузка файла пересоздаёт `Editor` (`app_external_changes_methods.rs:38,43,214,219`; `set_original_text` обнуляет `git_base_text`, `editor_core.rs:565-569`) и baseline сейчас не перезагружает. Новое: при перезагрузке снимок загружается заново, а `GitBlameState` (blame, кэш сообщений, флаг колонки) переносится из старого `Editor` в новый (после `set_original_text`, чтобы обнуление его не задело); blame остаётся, если ключ снимка не изменился, иначе перезапрашивается.
- Blame запускается **по oid из снимка**, не по символическому `HEAD`: `git blame --porcelain <head_oid> -- <rel_path>`. Результат применяется, только если его `(repo_root, rel_path, head_oid)` совпадает с текущим снимком таба (иначе отбрасывается, как `git_diff.rs:835`).
- Функции загрузки HEAD-baseline выносятся из `git_diff.rs` (1586 строк, лимит 1600) в новый `src/app/git_baseline.rs` вместе с проверкой HEAD ниже.

### Обновление при смене HEAD

Сигнала сейчас нет: после commit/checkout `git_hunks` считаются от старого HEAD. Новый механизм (полезен и существующим gutter-маркерам):

- Проверка HEAD: дешёвое `repo.head()` → oid для каждого репо, у которого есть открытые табы, сравнение с oid снимков табов.
- Когда проверяется: после завершения любой Git-операции панели (commit, checkout, pull, reset, stash…), при получении окном фокуса, при событии файлового watcher'а внутри `.git` репо (если watcher туда не смотрит — только первые два триггера; план проверяет), при активации таба. Независимо от того, открыта ли панель Git.
- Oid изменился или у таба репо снимка нет (но файл в workspace с репо) — перезагрузить снимок этих табов и, если blame нужен, перезапросить blame.

### Источник blame

- Новая `pub(crate)` обёртка в `src/app/git_panel/git_process.rs` (сейчас `git_output` приватный, `git_process.rs:115`), возвращающая stdout с bounded timeout; запуск в фоне через `ui_waker.spawn_one_shot` по образцу git diff (`git_diff.rs:689-724`, poll `774-797`).
- Blame нужен, когда inline включён или в табе открыта колонка; запрос — при появлении/смене снимка или при включении режима для уже открытого таба. На ключ — одна попытка; ошибка не повторяется до нового ключа. Ошибку при явном включении колонки показать через `show_notice`.
- Porcelain даёт `author`, `author-mail`, `author-time`, `summary`; полного сообщения нет. Полное сообщение для попапа подгружается лениво при открытии попапа: git2 `find_commit(oid).message()` в фоне, кэш по oid в состоянии blame таба.

### Сопоставление строк

- Строки буфера сопоставляются с HEAD через `Editor::git_hunks: Vec<LineDiffHunk>` (`src/editor/editor_core.rs:46-51`; `before_*` — HEAD baseline, `after_*` — буфер, `editor_core.rs:655,676`). Схема корректна и для рабочего дерева, изменённого до открытия: baseline и blame — один снимок.
- Условие показа: снимок есть, `head_oid` и `path_in_head` заданы, blame для того же ключа загружен. Пустые `git_hunks` при `git_base_text == None` (`editor_core.rs:573-583`) не означают совпадения с HEAD — без снимка аннотаций нет.
- `head_line_for(hunks, current_line) -> Option<usize>`: бинарный поиск по `after_start` (hunk'и упорядочены), строка внутри `after_start..after_end` — `None`; иначе сдвиг накопленной разницы. Колонка считает отображение для видимых строк за O(V log H), без аллокаций.

### Состояние

- Типы данных (`GitHeadSnapshot`, `GitBlameState`, парсер porcelain, `head_line_for`) — в `src/editor/git_blame_state.rs`, без зависимостей от `crate::app` (сейчас `src/editor` от `app` не зависит). Логика App (запросы blame, проверка HEAD, переход в граф, обработчики UI) — в `src/app/git_blame.rs` (AGENTS.md: логика фичи — в своём типе, `impl App` только маршрутизирует).
  - `GitBlameState` (поле `Editor` рядом со снимком): ключ, таблица коммитов (`oid`, `author`, `author_mail`, `author_time`, `summary`, ленивое полное сообщение), `Vec<u32>` индекс коммита на HEAD-строку, готовые подписи колонки и ранг возраста (считаются один раз при приходе результата), флаг «колонка открыта», поколение для отбрасывания устаревших ответов.
  - Парсер porcelain — чистая функция с unit-тестами; некорректный вывод → blame отсутствует, без паники.
- `Config` (`src/state_persistence.rs`, по образцу `ctrl_wheel_multiplier` `:28,46,625,755`): `git_blame_inline: bool`, `git_blame_delay_ms: u32` (default 400, нормализация `0..=2000`, шаг 100).

### Задержка inline

- Dwell-ключ: (таб, строка курсора, версия буфера, поколение снимка/blame). Любое изменение ключа (смена строки, переключение таба на той же строке, правка без перемещения, обновление снимка или blame) прячет аннотацию и попап и перезапускает таймер.
- Аннотация показывается через `git_blame_delay_ms` после последней смены ключа. Пробуждение — дедлайном в существующем сборе дедлайнов (`deadline_wake_at`, `src/app/events/about.rs:271`; образец hover — `src/app/events/about/about_tick_scroll_sections.rs:193-198`), без постоянной перерисовки.
- Текст аннотации (с относительной датой) форматируется один раз при показе в буфер состояния; в кадре — только отрисовка.

### Рендер

- Inline-аннотация: в текстовом слое редактора после конца строки курсора, только если строка видима и аннотация целиком помещается до правого края видимой области (решение 6). Регистрирует hit-rect для hover-попапа. Baseline — тот же округлённый, что у текста строки (AGENTS.md, Render Hot Paths). Не рисуется, пока открыт `inline_git_popup` той же строки (`dump.rs:232`) — план сверяет, что это за попап, и выбирает приоритет.
- Колонка (PR B): `editor_left_padding_for` (`src/render_view/root_helpers.rs:43-63`, свободная функция; вызовы — `root_frame_layout_renderer.rs`, `markdown_scroll_transition.rs:676`) получает ширину колонки параметром; рисуется в `draw_root_editor_gutter` (`src/render_view/root_frame_editor_text_renderer.rs:353-538`) по видимым строкам; на каждую видимую подпись — hit-rect (`UiId` с индексом строки) для hover и клика. Подписи — готовые из `GitBlameState`.
- Попап. Тултип графа завязан на граф: `draw_git_graph_tooltip(commit: &GitGraphCommit, target, commits, …, copied_commit: Option<(usize, usize)>, …)` (`ide_panel_git_tooltip_renderer.rs:723-735`), hover и `UiId::GitGraphCopyCommit/GitGraphOpenCommit` по индексам снимка графа, счётчики веток, stats, branch chip, `short_oid`, нет email и полного сообщения. Решение: ввести модель `CommitDetails { oid, short_oid, author, author_mail, time, summary, message: Option<String> }` и вынести отрисовку текстовых строк деталей (автор/дата/сообщение/хэш) в общую функцию; граф строит `CommitDetails` из `GitGraphCommit` и сохраняет свои stats/ветки/кнопки; blame-попап — свой тип с собственными `UiId` без индекса графа (`GitBlameCopyHash`, `GitBlameShowInGraph`), своим hover/copied-состоянием. Поведение тултипа графа не меняется (его тест `ui_tests_git_graph.rs:91` остаётся зелёным).
- Статус-бар: сегмент `Blame` по образцу `UiId::StatusDiagnostics` (`ide_panel_dialog_renderer.rs:413`, обработчик `ui_panels.rs:25`), виден когда `git_blame_inline` включён; клик выключает.
- Сообщения — существующий `App::show_notice` (`git_diff.rs:1444-1450`, рисуется `main_frame.rs:184-186`, гаснет `about_tick_scroll_sections.rs:421-425`, в dump `readonly_notice`); принимает сейчас `&'static str` — расширяется до владеющей строки для текста ошибки git. Второй механизм не заводится.

### Переход в граф

- Метод `App`: сделать видимой панель Git, выбрать workspace файла (`select_git_graph_workspace`, `git_panel_app_graph_methods.rs:290`; не `ensure_git_graph_loaded` — он берёт первый workspace с репо, `:428-462`), открыть нижнюю панель графа, если она закрыта (не `toggle_git_graph` — он закрывает открытый, `git_panel_types.rs:835-840`).
- Поиск по `GitGraphCommit.oid` в `graph_snapshot`; нет — догружать страницы (`load_more_git_graph_commits`, шаг 200, `git_panel_app_graph_methods.rs:501`) до находки, `graph_has_more == false`, ошибки загрузки, страницы без прогресса или длины `graph_snapshot` ≥ 5000 (считается по уже загруженному, догрузка не превышает 5000). Каждая страница — `git log --numstat` (`git_panel_graph_helpers.rs:424-432`): до 25 последовательных запросов, асинхронно, UI не блокируется; пока ищем — notice «Searching commit…», продлевается с каждой страницей (сейчас notice гаснет через 2 с, `git_diff.rs:1447`).
- Состояние поиска `GitGraphReveal { workspace_idx, oid, generation }` — в своём типе вне `git_panel_types.rs` (1586 строк; файл выбирает план с учётом лимита), `GitPanelState` получает одно поле. Отмена: закрытие графа, смена workspace графа, новый запрос перехода, refresh графа.
- Найден — прокрутить `graph_scroll` так, чтобы строка была видна, подсветить строку (по oid, не по индексу). Подсветка снимается кликом в графе, закрытием графа, новым переходом.
- Не найден/ошибка — `show_notice` «Commit not found in loaded history».

## Производительность

- Blame — одна команда git на ключ (oid HEAD + файл), в фоне. Правки буфера не вызывают git. Проверка HEAD — `repo.head()` по событиям, не по кадрам.
- В кадре: inline — готовая строка; колонка — готовые подписи видимых строк и `head_line_for` бинарным поиском.

Образцы: `headless_git_graph_commit_click_shows_details_and_copies_hash` (`ui_tests_git_graph.rs:91`), `ui_tests_hotkeys_feature_commands.rs:33,57`. Dump расширяется полями: текст и rect inline-аннотации, видимость индикатора `Blame`, подсвеченный oid графа, состояние колонки (открыта, подписи видимых строк). Фикстура: репо с ≥2 коммитами разных авторов и дат (блоки), для поиска в графе — история >200 коммитов.

PR A:
- переключатель во вкладке Git включает режим, появляется индикатор `Blame`; значение переживает сохранение/загрузку config;
- после задержки на закоммиченной строке — аннотация с автором и summary нужного коммита; до задержки — нет; смена строки, переключение таба, правка строки прячут и перезапускают задержку; пробуждение по дедлайну без холостых кадров (`wake`/`idle`);
- изменённая строка — без аннотации; строка ниже вставленного блока — верный коммит (сдвиг через hunk'и); файл, изменённый на диске до открытия, — верная атрибуция;
- коммит из панели Git (смена HEAD) — снимок и аннотация обновляются (бывшая изменённая строка получает новый коммит);
- длинная строка — без аннотации;
- soft wrap: перенесённая строка курсора — аннотация после последнего визуального сегмента и только если помещается;
- внешнее изменение файла на диске (перезагрузка таба) — аннотация возвращается после перезагрузки;
- клик по `Blame` в статус-баре выключает режим;
- наведение на аннотацию — попап с хэшем/автором/email/сообщением (полное сообщение подгружается); копирование хэша; попап закрывается при уходе мыши;
- «Показать в графе» открывает граф и подсвечивает коммит; коммит за пределами первой страницы находится догрузкой; не найден за лимитом (лимит подменяется в `cfg(test)`) — notice; подсветка снимается кликом в графе и закрытием графа;
- настройка задержки `-`/`+` меняет значение в пределах и сохраняет;
- файл вне репо, untracked, unborn HEAD — аннотаций нет, ошибок нет;
- тест тултипа графа (`ui_tests_git_graph.rs:91`) не меняется и зелёный.

PR B:
- правый клик по номерам строк открывает меню; по тексту — не открывает; пункт включает колонку; подписи только на первой строке каждого блока; повторный правый клик — «Close», колонка закрывается, ширина gutter возвращается;
- колонка per-tab: переключение на другой таб и обратно сохраняет состояние; внешняя перезагрузка файла колонку не закрывает;
- soft wrap: подпись блока — на первом визуальном сегменте первой строки блока, на сегментах переноса подписи нет;
- строки, изменённые относительно HEAD, без подписи;
- наведение на подпись — попап; левый клик — переход в граф с подсветкой.

Unit: парсер porcelain (несколько коммитов, повтор коммита без заголовков, `boundary`, нулевой oid, некорректная строка), `head_line_for` (вставка, удаление, удаление на границе, замена, несколько hunk'ов, строка внутри hunk, последняя пустая строка, тысячи hunk'ов), группировка блоков, ранг возраста, относительная дата, нормализация задержки, отмена `GitGraphReveal`.

Негативные входы: пустой файл, файл из одной строки без перевода строки, некорректный вывод blame, не-ASCII имя автора, длинное (многострочное) сообщение коммита.

## Вне объёма

Blame как текст в статус-баре, blame предыдущей ревизии, blame-сводка над функцией (последний автор и число авторов функции, как GitLens в CodeLens), blame несохранённого буфера через `--contents`, blame незакоммиченного переименования, переход к коммиту за пределами 5000, просмотр диффа коммита, перевод синхронной загрузки baseline в фон.
