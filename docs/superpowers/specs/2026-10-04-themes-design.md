# Темы редактора и интерфейса — дизайн

Карточка Kanri `kmnc7k7g` «поддержку тем для редактора и для подсветки». Дата: 2026-10-04.

## Цель

Пользователь выбирает тему в настройках. По умолчанию одна тема применяется и к редактору (текст, подсветка), и к интерфейсу; переключатель позволяет выбрать их раздельно. Пять тем: три тёмные и две светлые, одна из светлых — Sepia, «как книга».

## Решения пользователя

* Темы: **Dracula** (текущие цвета текста и интерфейса без изменений, тема по умолчанию), **One Dark**, **Forest** (тёплая зелёно-серая, в духе Everforest) — тёмные; **Sepia**, **One Light** — светлые.
* Настройки, вкладка «Внешний вид»: переключатель «Одна тема для редактора и интерфейса» (по умолчанию включён). Включён — один список «Тема»; выключен — два списка «Тема редактора» и «Тема интерфейса». Список — 5 строк с цветными образцами, выбор кликом, применяется сразу, без перезапуска.
* Граница: **тема редактора** — текст редактора, подсветка синтаксиса, гуттер (номера строк, git-метки, диагностика), миникарта, поиск по тексту и diff-оверлей в редакторе, Markdown Reader, терминал (фон, текст, 16 ANSI-цветов), фон поверхности окна (`EDITOR_SURFACE_BG`). **Тема интерфейса** — всё остальное: панели, вкладки, дерево файлов, Git, API Client, базы данных, диалоги, настройки, строка состояния, hover/LSP-попапы, скроллбары.
* Цвет выделения: Dracula сохраняет текущую логику (KDE `Colors:Selection` → системный акцент → `DEFAULT_ACCENT_COLOR`, `src/startup_environment.rs:136-161`); остальные темы задают свой.
* PDF: у темы есть признак `is_dark`. Смена темы редактора выставляет `pdf_dark_pages = editor_theme.is_dark()` через общий setter `set_pdf_dark_pages(bool)` (он же делает `bump_render_gen()` для всех PDF, как сейчас `toggle_pdf_dark_pages`, `src/app/pdf_tab/engine.rs:334-338`; toggle переходит на него); ручной переключатель (`UiId::PdfDarkToggle`) работает как раньше до следующей смены темы. Сохранённое значение при запуске не перезаписывается.
* Картинки не трогаем.
* Два этапа, два PR, оба в этой задаче подряд.

## Архитектура

### Модуль `src/theme.rs` (+ `src/theme/` при необходимости)

* `ThemeId { Dracula, OneDark, Forest, Sepia, OneLight }`: `ALL`, `label()` (как показывать), `key()` / `from_key()` для конфига (`"dracula"`, `"one_dark"`, `"forest"`, `"sepia"`, `"one_light"`; неизвестный или отсутствующий ключ → `Dracula`), `is_dark()`.
* `SyntaxPalette` — цвета ролей подсветки вместо `DRACULA_*`: `fg, comment, keyword, keyword_control, function, string, constant, parameter, class, md_code` и служебные `delimiter, tree_guide, log_text` (см. «Подсветка»). Соответствие текущим константам (для Dracula значения совпадают побитно): `fg`=`DRACULA_FG`, `comment`=`DRACULA_COMMENT`, `keyword`=`DRACULA_CYAN`, `class`=`DRACULA_DARK_CYAN`, `function`=`DRACULA_GREEN`, `parameter`=`DRACULA_ORANGE`, `keyword_control`=`DRACULA_PINK`, `constant`=`DRACULA_PURPLE`, `string`=`DRACULA_YELLOW`, `md_code`=`MARKDOWN_GOLD`. Правила `resolve_color` (какое capture-имя какой роли) не меняются.
* Палитра редактора — расширенный `Theme`: текущие 11 полей, плюс `surface_bg` (бывший `EDITOR_SURFACE_BG`), `syntax: SyntaxPalette`, `terminal: [[f32; 4]; 16]`, роли редакторских оверлеев, которые сейчас литералы: поиск (`SEARCH_HIGHLIGHT_COLOR`, `SEARCH_ACTIVE_HIGHLIGHT_COLOR`, `root_helpers.rs:2-3`), diff-оверлей (`[0.18, 0.82, 0.34, 0.26]`), и прочие литералы редакторской области, найденные при переносе. Для Dracula — текущие значения побитно.
* `UiPalette` — роли интерфейса (этап 1 — только значения Dracula; этап 2 — окончательный список ролей и 4 остальные палитры). Стартовый список ролей: поверхности `bg_panel`, `bg_panel_alt` (полоса вкладок, заголовки, строка состояния), `bg_raised` (диалоги, меню, попапы), `bg_input`, `bg_bottom_panel` (alpha 0.80 сохраняется); линии `border`, `border_strong`; текст `text`, `text_dim`, `text_muted`, `text_on_accent`; `accent`, `accent_soft`; `ink` — база для оверлеев; `selection_bg`; `scrollbar`, `scrollbar_hover`; `shadow`; `icon`; сигналы `error`, `warning`, `success`, `info`, `link`. Метод `ink(alpha) -> [f32; 4]` заменяет полупрозрачный белый: белый в тёмных темах, `text` в светлых.
* Активная пара: `Renderer` хранит `theme: Theme` (редактор) и `ui: UiPalette` (интерфейс). Цвета — копии `[f32; 4]` в полях: чтение поля на кадр, без аллокаций.

### Единая точка смены темы

`App::apply_themes(&mut self, editor: ThemeId, ui: ThemeId)` — единственное место, где меняются темы (правило AGENTS.md «одна точка коммита»):

1. строит `Theme` и `UiPalette`, записывает в `App.theme`, `Renderer.theme`, `Renderer.ui` (две копии `Theme` меняются только здесь) и увеличивает `Renderer.theme_gen: u64`;
2. кэши, которые хранят вычисленные цвета (hover layout, thread-local кэш hover `hover_widget.rs:25`, растровые кэши иконок), сравнивают свой `theme_gen` с текущим и перестраиваются сами — новый кэш с цветами обязан делать так же;
3. при смене темы редактора — `set_pdf_dark_pages(editor.is_dark())`;
4. сохраняет конфиг и запрашивает перерисовку.

Стартовый путь использует тот же построитель тем без шагов 3–4. Смена только темы интерфейса не трогает редакторские кэши и PDF.

### Подсветка: спаны хранят роль

`ColorSpan { start, end, color: [f32; 4] }` → `ColorSpan { start, end, role: SyntaxRole }`, где `SyntaxRole` — `#[repr(u8)]` enum: десять ролей `SyntaxPalette` плюс `Delimiter` (`[0.6, 0.6, 0.65, 1.0]`, backtick-разделители, `src/lsp/protocol.rs:25-35`), `TreeGuide` (`[0.45, 0.45, 0.50, 1.0]`, символы дерева диагностики, там же), `LogText` (`[0.875, 0.882, 0.902, 1.0]`, текст LSP-лога, `src/lsp/lsp_manager_support.rs:218-222`) и `Interpolation` — маркер вместо sentinel `MARKER_INTERPOLATION` (не цвет, не рисуется как роль). Эти три роли добавляются в `SyntaxPalette` с Dracula-значениями побитно.

* Все 67 production-конструкторов `ColorSpan` (11 файлов) переходят на роли, включая литералы, численно равные `DRACULA_*` (`src/languages/python_highlight_spans.rs:1-15`, `src/lsp/protocol.rs:59-71`, `src/lsp/lsp_process.rs:125-136`, `src/lsp/hover.rs:967-1053`).
* Логика по цветам переходит на сравнение ролей: слияние по равенству (`highlighter_core.rs:46-66`, `:1203-1225`), фильтр «не fg» (`:525-531`, `highlighter_worker.rs:1078-1088`), sentinel и допустимые цвета rainbow brackets (`highlighter_core.rs:1268-1302`, `highlighter_runtime.rs:924-947`), догадка цвета при вставке (`highlighter_runtime.rs:579-585`, `:648-650`). Сравнение ролей не ломается, когда у темы две роли одного цвета (One Dark: `keyword` = `class`).
* Цвет вычисляется при отрисовке: общий helper текста со спанами (`src/render_view/core_text.rs:1183-1205`) и его вызывающие получают `&SyntaxPalette` той поверхности, на которой рисуют, и берут `palette.color(role)` — индекс в массив, без аллокаций; затухание alpha (hover, sticky lines, миникарта со смешением с фоном, `minimap_ui.rs:333-348`) применяется к результату как сейчас.
* Поток подсветки палитру не получает, подсветка при смене темы не пересчитывается. Кэши со спанами (API Mock, SQL, Git payload, неактивные вкладки, Markdown code-блоки) перекрашиваются сами. `ColorSpan` уменьшается с 32 до 24 байт.
* Кэш hover с RGB глифов (`src/app/mouse/hover_state_core.rs:38-52`, `hover_widget.rs:898-917`) хранит роль вместо RGB; если это шире задачи — сбрасывается по `theme_gen` (ниже).
* Markdown layout хранит битовые роли стилей, ячейки терминала — индексы палитры, миникарта RGB не кэширует (`markdown_read.rs:10-45`, `terminal.rs:23-42`, `minimap_ui.rs:13-20`): они перекрашиваются при отрисовке из активной палитры.
* `DRACULA_*`, `MARKDOWN_GOLD`, `MARKER_INTERPOLATION` удаляются; `resolve_color` возвращает `SyntaxRole` и вместе с ролями переезжает из `highlighter_core.rs` (1597 строк) в модуль подсветки/темы. Ожидаемые значения в тестах — роли, а где тест проверяет пиксельный цвет — цвета палитры `ThemeId::Dracula`.

### Настройки и конфиг

* `Config`: `theme_linked: bool` (по умолчанию `true`), `editor_theme: ThemeId`, `ui_theme: ThemeId` (по умолчанию `Dracula`); ключи `"theme_linked"`, `"editor_theme"`, `"ui_theme"` в том же `json!`-объекте и разборе по ключам; мусорное значение → значение по умолчанию.
* Вкладка «Внешний вид» — свой файл (`settings_ui.rs` у предела): строка-переключатель и 1–2 списка по 5 строк. Строка списка: образец (полоска фона темы и 3–4 цвета подсветки) и название; активная отмечена. `UiId::SettingsThemeLinked`, `UiId::SettingsThemePick { target: Editor|Ui|Both, id }`; обработчик в `src/app/ui_handlers/` вызывает `apply_themes`.
* Связанный режим: выбор задаёт обе темы. Выключение связи: `ui_theme` остаётся равной `editor_theme`. Включение: `ui_theme := editor_theme`.

### Терминал

Dracula — текущий `ANSI_16_COLORS` побитно. One Dark, Forest — канонические 16-цветные схемы этих тем. Обычный текст терминала — ANSI 7 (дефолт ячейки и SGR reset), фон по умолчанию — ANSI 0, поэтому в светлых темах (Sepia, One Light) 0/8 — светлые, 7/15 — тёмные (как в светлых схемах терминалов), остальные — из ролей подсветки темы. Требование: ANSI 7 к фону терминала ≥ 4.5, остальные цветные 1–6, 9–14 ≥ 3.0.

Фон нижней панели (alpha 0.80 сохраняется): во вкладке Terminal — `bg` темы редактора, во вкладке Problems — `bg_bottom_panel` темы интерфейса. Так текст терминала всегда лежит на фоне своей темы и в раздельном режиме.

### Интерфейс (этап 2)

Задача 2.0 этапа 2 — скрипт-инвентаризация литералов по файлам и кластерам: окончательный список ролей `UiPalette`, значения Dracula (самое частое значение кластера), таблица «литерал → роль» для агентов. Значения 4 остальных тем выводятся из их палитр редактора: `bg_panel`/`bg_panel_alt`/`bg_raised` — на 2–6 % темнее/светлее `bg` в сторону от текста, `text` = `fg`, `accent` — `keyword_control` (One Dark/One Light — `function`), сигналы — `diag_error`/`diag_warn`/`modified_saved`/`keyword`.

Правило переноса — Dracula побитно: литерал заменяется ролью только при точном совпадении значения и одинаковом назначении; иначе — новая роль. Ролей может выйти 50–80, это нормально: цена — строки в таблице палитр, а не изменение Dracula. Локальной константой остаётся только цвет, действительно не зависящий от темы (цвет-метка подключения БД, выбранный пользователем). Таблица задачи 2.0 — «место (файл:строка) → роль → точное значение Dracula», её утверждаю я до раздачи файлов агентам; агенты не заводят ролей сами, а при несовпадении останавливаются с отчётом. Перенос охватывает и литералы, и обращения UI-файлов к полям редакторской темы (`theme.fg`, `theme.bg`, … — 444 обращения): каждое становится ролью `UiPalette` или остаётся редакторским, если рисует редакторскую область.

Текст с подсветкой на поверхностях интерфейса (hover/LSP-попап, код в API Client, SQL preview, Git diff в панели) красится `SyntaxPalette` темы интерфейса — той, на чьём фоне лежит; в области редактора — `SyntaxPalette` темы редактора. Каждая `ThemeId` даёт обе палитры, `Renderer` держит обе активные.

## Этапы

**Этап 1 (PR 1)** — `theme.rs`, `ThemeId`, `SyntaxPalette`, расширенный `Theme` с 5 палитрами редактора, подсветки и терминала; `UiPalette` со значениями Dracula; перевод `DRACULA_*`/`resolve_color`/`ANSI_16_COLORS`/`EDITOR_SURFACE_BG`/литералов редакторской области на палитру; `apply_themes`; конфиг (все три поля); вкладка «Внешний вид» с одним списком «Тема» (через `UiPalette`); PDF. Интерфейс вне редактора остаётся Dracula. Переключатель раздельного режима, список «Тема интерфейса» и иконки файлов `_dark` — в этапе 2, чтобы в PR 1 не было контрола, который ничего не меняет.

**Этап 2 (PR 2)** — задача 2.0 (инвентаризация и таблица «место → роль → Dracula»); перенос ~1000 литералов и UI-обращений к `theme.*` параллельными агентами по группам файлов (без пересечения файлов); 4 палитры интерфейса; переключатель раздельного режима и список «Тема интерфейса»; альфа-иконки на `ui.icon`; иконки файлов `_dark`; проверка цветных иконок.

## Проверки

* Юнит-тест контраста для всех 5 тем: `fg`/`bg` ≥ 4.5; каждая роль подсветки кроме `comment` ≥ 3.5 к `bg`; `comment` и `line_num` ≥ 2.5; терминал: ANSI 7 ≥ 4.5, цветные 1–6/9–14 ≥ 3.0 к фону терминала; этап 2 — `text`/`text_dim` ≥ 4.5/3.0 к каждому фону интерфейса. Dracula (calibrated: `fg` 13.4, `comment` 3.0) проходит.
* Тест побитного совпадения Dracula: палитра `ThemeId::Dracula` равна прежним константам (`DRACULA_*`, `MARKDOWN_GOLD`, `ANSI_16_COLORS`, `EDITOR_SURFACE_BG`, значения `load_dracula`).
* Конфиг: round-trip трёх полей; мусорный ключ темы → `Dracula`; отсутствующие поля (старый конфиг) → значения по умолчанию.
* `apply_themes`: после смены темы спан ключевого слова в открытом буфере (и в неактивной вкладке) рисуется цветом роли новой палитры, без нового запроса подсветки; `theme_gen` растёт и hover-кэш перестраивается; `pdf_dark_pages` следует `is_dark` и PDF перерисовывается; смена только UI-темы не трогает PDF; связанный режим задаёт обе темы.
* Роли: юнит-тесты слияния спанов и rainbow brackets на ролях проходят с палитрой, где две роли одного цвета.
* Headless-сценарий настроек: клик по строке темы в связанном и раздельном режимах, `dump` показывает выбранные темы.
* Снимки (`rriter_headless.py shot`): этап 1 — редактор с Python-файлом и Markdown во всех 5 темах; этап 2 — Dracula до/после переноса (визуально без изменений) и ключевые экраны (дерево, Git, API Client, БД, настройки, диалог) в 5 темах.

## Не входит

Картинки; пользовательские темы из файлов; импорт тем VS Code; редактор цветов.
