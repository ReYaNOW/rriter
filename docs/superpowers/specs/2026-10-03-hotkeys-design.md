# Переназначаемые горячие клавиши — дизайн

Дата: 2026-10-03. Ветка `hotkeys`. Kanri: x6nenctesmydnrdd6l32g0iu.

## 1. Цель и границы

Пользователь переназначает сочетания клавиш команд приложения во вкладке Settings «Горячие клавиши» и в `config.json`. Сочетания по умолчанию остаются такими, как сейчас (инвариант §8), кроме случайных нестрогих вариантов (§3.3).

Переназначаемы:
* все команды приложения, которые сейчас вызываются сочетанием с модификатором (Ctrl/Cmd/Alt/Shift в любой комбинации) или F1–F12 / Insert / Pause без модификатора — около 90 мест диспатча, точный список даёт инвентаризация (§8.1);
* 24 новые команды без сочетания по умолчанию (§4.3).

Не переназначаемы (фиксированы, список `RESERVED`, §3.4): стрелки, Home/End, PageUp/PageDown, Backspace/Delete, Enter, Tab, Escape и их Shift- и word-варианты (word-модификатор — `platform::word_navigation_modifier`); навигация в попапах (автодополнение, диалоги); трансляция клавиш терминала в байты (`terminal_key_sequence`); собственные клавиши редактирования однострочных полей ввода.

Вне scope: последовательности (chords из нескольких нажатий), пресеты (VS Code, JetBrains), подсказки сочетаний на кнопках-иконках, логические (раскладочные) клавиши.

## 2. Модуль `keymap`

Файлы: `src/keymap.rs` (типы, разбор, `Keymap`), `src/keymap/defaults.rs` (таблица `COMMANDS`). Модуль не зависит от `App`.

### 2.1 Команды

```rust
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum Command { Save, SaveAs, ..., GitPush, ... }   // один вариант на команду

pub enum KeyContext { Global, Editor, FileTree, Terminal, Pdf, Image, Database, ApiClient, Markdown, Settings, Welcome }

pub struct CommandInfo {
    pub command: Command,
    pub id: &'static str,          // "editor.save", "git.push" — ключ в config.json, стабилен
    pub label: &'static str,       // "Сохранить файл", "Git: отправить (push)"
    pub context: KeyContext,
    pub defaults: &'static [&'static str],  // "mod+s"; пусто у новых команд
}

pub const COMMANDS: &[CommandInfo];   // порядок = порядок в Settings внутри контекста
```

`COMMANDS` — единственный источник id, подписей, контекстов и умолчаний; `Command as usize` — индекс в `COMMANDS` (unit-тест проверяет совпадение). Набор `KeyContext` уточняется инвентаризацией (§8.1): контекст — условие, при котором ветка диспатча достижима, а не файл, где она лежит.

### 2.2 Сочетание

```rust
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub struct Chord { pub key: KeyCode, pub mods: Mods }   // KeyCode — winit, физическая клавиша
bitflags Mods { CTRL, ALT, SHIFT, SUPER }
```

* Текстовый формат: токены в нижнем регистре через `+`, клавиша последней: `mod+shift+f`, `alt+q`, `f5`, `ctrl+alt+q`. Модификаторы: `ctrl`, `alt`, `shift`, `cmd`/`super` (синонимы → `SUPER`), `mod`. Имена клавиш — таблица из `KeyInput::parse_combo` (`src/app/keyboard/key_input.rs:50`): разбор токена клавиши выносится оттуда в общую функцию и используется обоими, без копии. Порядок модификаторов в строке не важен, повтор — ошибка.
* Таблица имён клавиш дополняется тем, что нужно умолчаниям и §2.3: `pause`, `insert`, `numpadenter` и другие клавиши, которые инвентаризация (§8.1) найдёт в текущих ветках; headless-команда `key` получает их же.
* `mod` разрешается при разборе: `SUPER` на macOS, `CTRL` на остальных. В `Chord` хранится уже разрешённый модификатор, поэтому сравнение платформенно-независимо.
* Сериализация: если сочетание содержит основной модификатор платформы (`CTRL` вне macOS, `SUPER` на macOS), он пишется как `mod`; второй — явно (`ctrl` на macOS). Порядок записи: `mod`, `ctrl`, `cmd`, `alt`, `shift`, клавиша.
* Отображение: Linux/Windows — `Ctrl+Shift+F`, `Alt+Q`, `F5`; macOS — символы `⌃⌥⇧⌘` в порядке Apple и клавиша: `⌘⇧F`, `⌥Q`.

### 2.3 Допустимость сочетания

`validate(chord) -> Result<(), ChordError>`:
* `Reserved` — сочетание из `RESERVED` (§3.4);
* `NeedsModifier` — клавиша — буква, цифра или знак, а модификаторов нет или только `SHIFT` (Q14);
* голый Escape — всегда `Reserved` (Escape отменяет запись; с модификатором допустим);
* без модификатора допустимы только F1–F12, Insert, Pause.

### 2.4 `Keymap`

```rust
pub struct KeymapOverrides { raw: BTreeMap<String, serde_json::Value> }  // как в config.json, включая ошибочные записи
pub struct Keymap {
    chords: Vec<SmallVec<[Chord; 3]>>,   // индекс — Command
    labels: Vec<String>,                 // отображение первого сочетания или «не назначено»
    skipped: Vec<SkippedEntry>,          // для красной строки и лога
}
impl Keymap {
    pub fn build(overrides: &KeymapOverrides) -> Keymap;
    pub fn hit(&self, cmd: Command, chord: Chord) -> bool;   // linear по ≤3 элементам
    pub fn chords(&self, cmd: Command) -> &[Chord];
    pub fn label(&self, cmd: Command) -> &str;
    pub fn owners_of(&self, chord: Chord, ctx: KeyContext) -> SmallVec<[Command; 2]>;  // все конфликтующие, вне горячего пути
}
```

* `KeymapOverrides` — единственный владелец пользовательских данных; `Keymap` всегда строится из него целиком (`build`) после каждого изменения. Поле `App.keymap` и `App.keymap_overrides` меняются только методом `App::set_keymap_overrides(new)`, который пересобирает `Keymap`, сохраняет конфиг и обновляет подписи (§6) — одна точка фиксации (AGENTS.md §5 Design).
* `hit` не аллоцирует и не хеширует; `Chord` события вычисляется один раз на нажатие (§3.1).

## 3. Диспатч (O1)

### 3.1 Сочетание события

`Chord::from_event(platform: PlatformKind, ev: &KeyInput, modifiers: ModifiersState) -> Option<Chord>` в начале обработки нажатия (только `Pressed`; повтор обрабатывается так же, как сейчас обрабатывает каждая ветка). `KeyInput` (`src/app/keyboard/key_input.rs:4-13`) несёт физическую клавишу и текст. Для `PhysicalKey::Unidentified` — `None`, ни одна команда не срабатывает. Та же функция используется при записи сочетания (§5.3) — политика записи и диспатча одна.

Windows AltGr: Windows сообщает AltGr как Ctrl+Alt (`src/platform.rs:341-352`). Правило: на Windows при нажатых Ctrl и Alt `from_event` возвращает `None`, если текст события непуст и не управляющий символ (это набор символа, например `@` на немецкой раскладке); иначе — обычное сочетание `ctrl+alt+…`. Правило новое: сегодня Ctrl+Alt на Windows не бывает основным модификатором никогда, а Q2 разрешает назначать Ctrl+Alt-сочетания. Риск — мёртвые клавиши и композиция (событие без текста на AltGr-позиции даст сочетание); проверяется unit-тестами на синтетических событиях, реальное поведение winit на Windows — ручная проверка до релиза (R4).

### 3.2 Ветки остаются на месте

Ветки в `src/app/keyboard/main_keys.rs`, `src/app/keyboard/editor_keys.rs`, `src/app/keyboard.rs` и панельных файлах (PDF, изображение, дерево файлов, БД, markdown, API) остаются в том же порядке и с теми же условиями контекста (фокус, режим, активная вкладка). Меняется только проверка клавиши и модификаторов:

```rust
PhysicalKey::Code(KeyCode::KeyS) if ctrl => { ... }          // было
_ if self.keymap.hit(Command::Save, chord) => { ... }         // стало
```

Ветки, где одна команда сейчас ловится двумя проверками (redo — `Ctrl+Y` и `Ctrl+Shift+Z`), сводятся в одну `hit` с двумя умолчаниями. Уточнение после инвентаризации: в редакторе `Ctrl+Shift+Z` сегодня попадает в нестрогую ветку undo (`editor_keys.rs:793`), redo на нём есть только в однострочных полях; решение — у `Redo` редактора умолчания `mod+y` и `mod+shift+z` (осознанное изменение поведения, одобренное в этой спеке), undo теряет случайный вариант по §3.3. `Ctrl+Q`: на экране приветствия — `app.quit` в контексте `Welcome` (достижимость welcome-ветки `editor_keys.rs:450-487`, не только флаг), в IDE/редакторе — отдельная команда закрытия вкладок; `Welcome` и `Editor` — пара `exclusive`. Одно сочетание, означающее разные команды в разных контекстах (например, `Ctrl+C` в логе установщика и в редакторе), — разные `Command` с разными `KeyContext`.

Одна команда может законно проверяться в нескольких местах, если это одна команда в разных состояниях (`Open` — на экране приветствия и в редакторе, `src/app/keyboard/editor_keys.rs:452,786`). Unit-тест (`include_str!` диспатчеров) проверяет только, что у каждой `Command` из `COMMANDS` есть хотя бы одно место `hit(Command::X` — команда без ветки иначе молча не работала бы. Полноту перевода (не осталось старых проверок клавиш в ветках команд) проверяет характеризация §8.1 и ревью диффа по инвентаризации.

### 3.3 Точное совпадение модификаторов (Q20)

`hit` сравнивает модификаторы точно. Сегодняшние нестрогие ветки (`KeyS if ctrl` срабатывает и на `Ctrl+Shift+S`, `F1` — и на `Shift+F1`; инвентаризация нашла такое почти во всех местах) теряют случайные варианты. Намеренные варианты становятся явными умолчаниями. Это единственное разрешённое отличие от «как сейчас»; инвентаризация (§8.1) помечает каждый нестрогий вариант, который покрыт тестом или документацией, — он переносится в умолчания.

### 3.4 Резерв

Фиксированные ветки (§1: `Space`, стрелки, Escape, Enter и т. д.; на macOS также `Cmd+Home/End`, `editor_keys.rs:908,918`) сегодня тоже нестрогие: ветка Escape (`editor_keys.rs:1081`) съедает и `Ctrl+Escape`, ветка `Space` без проверки модификаторов — например `Alt+Space` (`Ctrl+Space` — команда автодополнения, `editor_keys.rs:1070`). Поэтому назначенная команда на такое сочетание не сработала бы, если её ветка стоит ниже.

Решение: фиксированные ветки получают точную проверку модификаторов — ту же, что у команд (§3.3). `RESERVED` — это ровно множество сочетаний, которые принимают фиксированные ветки после этой правки; оно составляется инвентаризацией по фактическим веткам, а не по шаблону «клавиша + word-модификатор», и лежит в `src/keymap.rs` как функция `is_reserved(chord)`. Фиксированные ветки проверяют модификаторы через неё же, поэтому список и ветки не расходятся. Сочетание, которое уже является командой (`Ctrl+Enter` — запуск SQL, `main_keys.rs:383`; `Alt+Enter` — меню действий LSP, `editor_keys.rs:626`), в `RESERVED` не входит. Собственные клавиши редактирования однострочных полей (clipboard, select all, undo/redo поля — §1) — отдельная категория «фиксированные локальные операции ввода»: сочетания и место обработки сохраняются, на `hit` не переводятся, в `RESERVED` не входят и переназначениям команд редактора не следуют (рекомендация инвентаризации §2 перевести их на `hit` отменена). Глобальный `is_reserved` не заменяет проверку отдельной фиксированной ветки: ветка проверяет свои допустимые варианты (из таблицы инвентаризации), `is_reserved` — их объединение. Следствие: нестрогие варианты фиксированных клавиш (`Alt+Space` вставляет пробел) пропадают так же, как у команд (Q20), и становятся свободны для назначения. Записать `RESERVED`-сочетание нельзя (§5.3), в конфиге оно пропускается (§7).

### 3.5 Терминал (Q10)

Терминал в фокусе по-прежнему забирает свои сочетания — порядок и условия веток не меняются. Keymap влияет только на команды приложения. Сегодня приоритет терминала держится на условиях отдельных глобальных веток, и он неоднороден: часть глобальных веток стоит выше терминала и срабатывает в его фокусе (`Ctrl+Shift+F`, `main_keys.rs:703`). После переназначения это дало бы разный приоритет одному сочетанию в зависимости от места ветки. Решение (уточнено после инвентаризации): безусловного раннего перехода в PTY нет — модалки, Settings, поля ввода и поиск терминала сегодня забирают клавишу раньше терминала (`main_keys.rs:180-300`, `keyboard.rs:643-663`), и порядок сохраняется. Передача в терминал остаётся в финальной маршрутизации (`main_keys.rs:~841`); ветки команд, стоящие выше неё, проходят через шлюз-предикат `terminal_gate(chord)`: `Pressed && IDE && terminal_open && terminal_focused && !terminal_search_owner && !editor_search_owner && !higher_input_owner && terminal_intercepts(chord)` → команда не срабатывает, событие идёт дальше к терминалу. `higher_input_owner` — существующие поглощающие обработчики (модалки, Settings, поля, API catch-all) в их текущем порядке; `terminal_owns_keyboard_context` для шлюза непригоден (истинен при фокусе поиска терминала, `main_keys.rs:96`). Предикат — одна функция, её же зовёт финальная маршрутизация (инвентаризация §12). Исключения из шлюза — конкретная пара «команда + исходное сочетание + прежние условия», сохраняющая сегодняшний приоритет: копирование/undo таблицы БД (`database_table_edit_methods.rs:931-935`), копирование графа Git (`main_keys.rs:732-746`), clipboard дерева файлов — только если совместный фокус дерева и терминала достижим (проверяет характеризация Task 2). Переназначенное на перехватываемое сочетание исключения не наследует. Перехваты терминала — функция `terminal_intercepts(chord) -> bool` рядом с `terminal_key_sequence`, составленная по его фактическим веткам: `Ctrl+A`–`Ctrl+Z` (управляющие байты, буквальный Ctrl на всех платформах), `Primary+F` (поиск), `Primary+V` (вставка), `Primary+C` (копирование выделения) — на macOS это `Cmd+F/V/C` (`src/app/keyboard.rs:491-549`). Точный набор — платформенная таблица по фактическим веткам и `terminal_key_sequence` (там же `Ctrl+Space` и пунктуация, `keyboard.rs:115,123,146`); составляет её Task 5. Если пользователь назначает глобальной команде такое сочетание, вкладка показывает предупреждение «в фокусе терминала перехватывается терминалом», запись не блокируется.

### 3.6 Фильтры по клавишам

Кроме веток команд, в коде есть фильтры безопасности, перечисляющие клавиши. Главный — `pdf_tab_key_reaches_editor` (`editor_keys.rs:86`, вызов `:489`): на вкладке PDF/изображения в редактор пропускаются только F1, Escape и `Primary+Q/F/O/4`, всё остальное блокируется, потому что скрытый редактор под PDF затёр бы файл (`Ctrl+S` записал бы пустой текст в `.pdf`). Если оставить фильтр по клавишам, после переназначения `Save` на `mod+o` сохранение пройдёт фильтр и испортит PDF; а `Find`, переназначенный на `mod+g`, перестанет работать на PDF.

Решение: такие фильтры переписываются на команды. `pdf_tab_key_reaches_editor(chord, &keymap)` пропускает событие, только если сочетание попадает хотя бы в одну из команд `{Settings, CloseAllTabs, Find, OpenFile, CloseTab}` (точный набор — по текущему фильтру, инвентаризация) и ни в одну другую команду редактора (сочетание, общее с `Save` из-за ручного конфликта в конфиге, блокируется), или это голый Escape; фиксированные клавиши (ввод, навигация) блокируются как сейчас. Инвентаризация (§8.1) перечисляет все фильтры по клавишам (поиск: функции/условия, перечисляющие `KeyCode` вне веток команд), и каждый переводится так же. Unit-тест: `Save`, переназначенный на `mod+o`, на вкладке PDF не доходит до редактора; `Find` на `mod+g` — доходит.

## 4. Новые команды

### 4.1 Диспатч

`App::run_command(cmd: Command) -> CommandOutcome` в `src/app/keyboard/commands.rs`; `enum CommandOutcome { Done, Unavailable(&'static str) }`. Вызывает те же методы, что обработчики `UiId` соответствующих кнопок (`src/app/ui_handlers/ui_git.rs`, `ui_lsp.rs`, `ui_database.rs`, `ui_editor.rs`, `api_client_app_click_methods.rs`), без копий логики; где обработчик кнопки принимает индекс (`GitPush(workspace_idx)`, `LspServerRestart(idx)`), команда берёт индекс активного репозитория / сервера активного документа, а общий код выносится в метод, который зовут оба.

Цикл по командам §4.3 — в `handle_main_keyboard_input_inner` непосредственно перед финальной маршрутизацией (`main_keys.rs:~836`: поиск терминала / терминал / поиск редактора / редактор), то есть после всех глобальных и панельных веток. Перехваты терминала сюда не доходят (шлюз §3.5). Контексту, чей обработчик раньше этой точки забирает любое нажатие (активная вкладка API Client: `main_keys.rs:775` → `api_client_app_request_methods.rs:415`), цикл вызывается ещё и на входе этого обработчика с фильтром по своему контексту: `run_bound_commands(chord, ctx)`; инвентаризация перечисляет все такие поглощающие обработчики. Цикл перебирает только команды, чей `KeyContext` сейчас активен (Global — всегда; Database — активна вкладка таблицы БД или SQL-консоль; ApiClient — открыт API Client; Editor — фокус в редакторе); первая команда, чей `hit` сработал, выполняется. Команда неактивного контекста не забирает клавишу, поэтому локальная привязка в другом контексте остаётся достижимой.

### 4.2 Неприменимая команда (Q22)

`Unavailable(причина)` — клавиша забрана, в статус-строку пишется причина («Git: нет активного репозитория», «Нет открытой таблицы БД»). Исключение: в фокусе терминал и сочетание из списка перехватов терминала (§3.5) — клавиша уходит терминалу, сообщения нет.

## 5. Вкладка Settings «Горячие клавиши» (Q9)

### 5.1 Размещение

Седьмая вкладка сайдбара после «Базы данных» (`src/render_view/settings_ui.rs:519`, массив `tabs`). Рендер — новый файл `src/render_view/settings_keymap_ui.rs` (`settings_ui.rs` уже 1520 строк). Состояние — `KeymapSettingsState` (фильтр — существующий однострочный ввод, прокрутка, `recording: Option<Recording>`, `pending_conflict: Option<Conflict>`, текст подсказки записи) с собственными методами; клики — новые `UiId` через `src/app/ui_handlers/ui_settings.rs`.

### 5.2 Раскладка

Сверху вниз: красная строка «пропущено N записей keymap» (если `skipped` не пуст; подробности — в логе); поле фильтра и кнопка «Сбросить все»; список по `KeyContext` с заголовками групп. Строка команды: подпись, мелкий id, чипы сочетаний с «×», кнопка «+», «↺» (только у команд, у которых есть ключ в `KeymapOverrides`). Изменённые команды выделены акцентом, конфликтующие (§7) — пометкой «конфликт».

Фильтр — подстрока без учёта регистра по подписи, id и отображаемым сочетаниям обеих форм (`ctrl+s` найдёт «Сохранить»). Строки — от округлённых базовых линий через существующие хелперы строк/прокрутки Settings; хитбоксы — только через `UiId`.

### 5.3 Запись

* «+» → чип «Нажмите сочетание…», `recording = Some`. Пока запись идёт, следующее нажатие перехватывается до любого диспатча (в начале `handle_main_keyboard_input_inner`, рядом со startup-gate); нажатия одних модификаторов игнорируются.
* Голый Escape или клик мимо чипа — отмена записи.
* `validate` → `Reserved` — подсказка «зарезервировано», `NeedsModifier` — «нужен Ctrl/Alt/⌘»; запись продолжается.
* Сочетание уже у этой команды — запись заканчивается без изменений.
* `owners_of(chord, ctx)` находит все команды с этим сочетанием во всех контекстах, совместимых с контекстом записываемой команды (правило R6: все пары, кроме `KeyContext::exclusive`; их может быть несколько) → строка «Занято: X, Y. Переназначить?» с [Да] / [Нет] (Q5). «Да» снимает сочетание со всех найденных и добавляет текущей команде одним `set_keymap_overrides`; «Нет» — отмена.
* Сочетание из перехватов терминала у глобальной команды — предупреждение §3.5, сочетание добавляется.
* «×» снимает сочетание (последнее снятое даёт `[]`). «↺» удаляет ключ команды. «Сбросить все» — через существующий диалог подтверждения, затем удаляет все ключи с известными id. Записи с неизвестными id остаются (§7).

## 6. Подписи в UI (Q12)

Тексты с сочетаниями строятся из keymap: `src/render_view/ui.rs:1471` («Ctrl+O — открыть файл»), `src/render_view/ide_panels/ide_panel_project_search_renderer.rs:519` («Ctrl+Enter …»), справка `FAQ_TEXT` (`src/app/app_bootstrap.rs:10`) и подписи в Settings, которые найдёт инвентаризация. `FAQ_TEXT` становится шаблоном: строки команд содержат `{cmd:<id>}`, подставляется `keymap.label`; строки фиксированных клавиш (`Ctrl + ←/→`, `Ctrl + Bksp`) остаются литералами. Готовые строки хранятся и пересобираются в `set_keymap_overrides`; в кадре — без `format!` и аллокаций. Команда без сочетания показывается как «не назначено».

## 7. Сохранение и ошибки (Q8, Q17)

* `Config.keymap: KeymapOverrides` (`src/state_persistence.rs:19`). Разбор — в `parse_config_content` из `serde_json::Value`: отсутствие поля или не-объект — пустые overrides и одна строка в лог. Запись — существующим атомарным `save_config`.
* Содержимое: только отличия. Нет ключа — умолчание; `[]` — сочетаний нет; список — замена умолчаний. Если после изменения набор равен умолчанию (без учёта порядка), ключ удаляется.
* Ошибки при `build`, каждая — строка в лог и элемент `skipped`:
  * неизвестный id или значение не массив строк — запись целиком пропущена;
  * неразборчивое сочетание, `validate`-ошибка — пропущено только оно, остальные сочетания записи действуют.
* Пропущенное сохраняется нетронутым (Q23): `KeymapOverrides.raw` хранит исходные значения. Записи с неизвестным id UI не трогает никогда. Значение-не-массив у известной команды обычная правка не трогает (команда работает по умолчанию, «+» и «×» у неё недоступны, есть только «↺»). В массиве известной команды правка из UI («+», «×», снятие при конфликте) меняет только действующие элементы, а пропущенные строки — неразборчивые и разборчивые, но недопустимые по `validate` — оставляет в массиве как есть. Явные действия «↺» и «Сбросить все» удаляют ключ известной команды целиком, вместе с его ошибочными элементами — это прямой запрос пользователя вернуть умолчание. Красная строка остаётся, пока пропущенное есть в файле.
* Конфликт из ручной правки (одно сочетание у двух команд в одном контексте или с `Global`) — обе привязки действуют, срабатывает та, чья ветка раньше; во вкладке обе строки помечены «конфликт». Через UI конфликт создать нельзя (§5.3).

## 8. Тесты

### 8.1 Инвентаризация и характеризация — первая задача, до изменения диспатча

Инвентаризация на текущем коде: для каждого места диспатча — `file:line`, клавиша, проверка модификаторов, контекст, действие, предлагаемые `id` и `KeyContext`, нестрогие варианты и где они покрыты тестом или документацией; фиксированные ветки и принимаемые ими сочетания (основа `RESERVED`, §3.4); фильтры по клавишам (§3.6); перехваты терминала (§3.5). Результат — `docs/hotkeys-inventory.md`, из него собирается `COMMANDS`.

Характеризация: табличный headless-тест на текущем коде — для каждой команды по умолчанию нажать сочетание в её контексте и проверить эффект через `dump`; команды без эффекта, видимого через `dump`, перечислены в тесте явно с причиной. После перевода на keymap тест проходит без правок.

### 8.2 Инвариант «умолчания не меняются»

Характеризационный тест §8.1 и существующие headless-тесты сочетаний (`ui_tests_editor.rs::headless_editor_save_undo_redo_shortcuts`, `ui_tests_editor_shortcuts.rs`, `ui_tests_keyboard_panels.rs`, `ui_tests_markdown*`, `ui_tests_pdf.rs`) проходят без правок. Исключение — тест, который проверяет нестрогий вариант, не перенесённый в умолчания по §3.3: такая правка теста перечисляется в отчёте задачи с причиной.

### 8.3 Unit (`src/keymap.rs`)

* разбор/сериализация/отображение, `mod` для Linux, Windows, macOS (через `PlatformKind`, как `primary_shortcut_for_platform`), повтор модификатора, пустой токен;
* точное совпадение модификаторов; AltGr Windows (Ctrl+Alt с текстом — `None`, без текста — сочетание);
* `validate`: голая буква, `shift+a`, голый Escape, `RESERVED`, `f5`, `insert`;
* `build`: неизвестный id, не-массив, не-строка в массиве, мусорное сочетание, `[]`, лишние поля, равенство умолчанию удаляет ключ; пропущенные записи переживают сохранение;
* `COMMANDS`: id уникальны, `Command as usize` = индекс, умолчания разбираются и проходят `validate`, нет конфликтов умолчаний в одном контексте и с `Global` (кроме перечисленных в инвентаризации существующих, если есть);
* у каждой команды есть место `hit(Command::X` (§3.2);
* `is_reserved` совпадает со списком фиксированных сочетаний из инвентаризации (табличный тест: каждое сочетание списка — `true`; выборка нестрогих вариантов, которые сегодня съедали фиксированные ветки, например `ctrl+escape`, `alt+space`, — `false`);
* у каждой команды из §4.3 есть ветка в `run_command`;
* фильтры §3.6: переназначенный `Save` не проходит фильтр PDF, переназначенный `Find` проходит;
* `terminal_intercepts` на Linux и macOS (`Cmd+C` перехват, `Ctrl+C` — байт).

### 8.4 Headless-сценарии

* переназначение через `config.json`: новое сочетание работает, старое — нет; `[]` снимает;
* вкладка: добавить сочетание, конфликт с «Да» и «Нет», отмена Escape, отказ на зарезервированное, «×», «↺», «Сбросить все» с подтверждением, фильтр по подписи и по сочетанию, красная строка пропущенных;
* команда §4.3 без условия — сообщение в статус-строке; с условием — эффект;
* терминал в фокусе забирает своё сочетание, назначенное глобальной команде.

## 9. Риски

* R1. Пропущенная ветка при переводе на keymap — команда перестаёт работать или остаётся непереназначаемой. Страховка — §8.1 и unit «у каждой команды есть место `hit`».
* R6. Конфликт между двумя локальными контекстами, которые бывают активны одновременно (Database и Editor), не ловится правилом «тот же контекст или Global». Правило конфликта (§5.3, §7): сочетание конфликтует во всех парах контекстов, кроме перечисленных в `KeyContext::exclusive(a, b)` как взаимоисключающие (например, Pdf и Image — одна активная вкладка); список пар даёт инвентаризация, по умолчанию пара считается совместимой.
* R2. Изменение порядка веток при правке `match` (ветка с `hit` вместо паттерна по клавише проверяется в той же позиции, но guard-only ветки в `match physical_key` должны идти до `_`-ветки по умолчанию). Страховка — характеризация.
* R3. Горячий путь: `hit` вызывается десятками веток на нажатие — линейный проход по ≤3 сочетаниям, без аллокаций; это нажатие, не кадр.
* R4. AltGr и мёртвые клавиши на Windows (§3.1) проверены только синтетически; до релиза — ручная проверка на немецкой/польской раскладке.
* R5. Пропущенный фильтр по клавишам (§3.6) — переназначенная команда обходит защиту. Страховка — пункт инвентаризации «фильтры по клавишам» и unit-тест PDF.
