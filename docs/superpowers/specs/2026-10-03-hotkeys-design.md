# Переназначаемые горячие клавиши — дизайн

Дата: 2026-10-03. Ветка `hotkeys`. Kanri: x6nenctesmydnrdd6l32g0iu.

## 1. Цель и границы

Пользователь переназначает сочетания клавиш команд приложения во вкладке Settings «Горячие клавиши» и в `config.json`. Сочетания по умолчанию остаются такими, как сейчас (инвариант §8), кроме случайных нестрогих вариантов (§3.3).

Переназначаемы:
* все команды приложения, которые сейчас вызываются сочетанием с модификатором (Ctrl/Cmd/Alt/Shift в любой комбинации) или F1–F12 / Insert / Pause без модификатора — около 90 мест диспатча, точный список даёт инвентаризация (§8.1);
* 24 новые команды без сочетания по умолчанию (§4.3).

Не переназначаемы (фиксированы, список `RESERVED`, §3.4): стрелки, Home/End, PageUp/PageDown, Backspace/Delete, Enter, Tab, Escape и их Shift- и word-варианты (word-модификатор — `platform::word_navigation_modifier`); навигация в попапах (автодополнение, диалоги); трансляция клавиш терминала в байты (`terminal_key_sequence`); собственные клавиши редактирования однострочных полей ввода.

Вне scope: последовательности (chords из нескольких нажатий), пресеты (VS Code, JetBrains), подсказки сочетаний на кнопках-иконках, логические (раскладочные) клавиши.

## 2. Модуль `keymap`

Файлы: `src/keymap.rs` (типы, разбор, `Keymap`), `src/keymap/defaults.rs` (таблица `COMMANDS`). Модуль не зависит от `App`.

### 2.1 Команды

```rust
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum Command { Save, SaveAs, ..., GitPush, ... }   // один вариант на команду

pub enum KeyContext { Global, Editor, FileTree, Terminal, Pdf, Image, Database, ApiClient, Markdown, Settings }

pub struct CommandInfo {
    pub command: Command,
    pub id: &'static str,          // "editor.save", "git.push" — ключ в config.json, стабилен
    pub label: &'static str,       // "Сохранить файл", "Git: отправить (push)"
    pub context: KeyContext,
    pub defaults: &'static [&'static str],  // "mod+s"; пусто у новых команд
}

pub const COMMANDS: &[CommandInfo];   // порядок = порядок в Settings внутри контекста
```

`COMMANDS` — единственный источник id, подписей, контекстов и умолчаний; `Command as usize` — индекс в `COMMANDS` (unit-тест проверяет совпадение). Набор `KeyContext` уточняется инвентаризацией (§8.1): контекст — условие, при котором ветка диспатча достижима, а не файл, где она лежит.

### 2.2 Сочетание

```rust
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub struct Chord { pub key: KeyCode, pub mods: Mods }   // KeyCode — winit, физическая клавиша
bitflags Mods { CTRL, ALT, SHIFT, SUPER }
```

* Текстовый формат: токены в нижнем регистре через `+`, клавиша последней: `mod+shift+f`, `alt+q`, `f5`, `ctrl+alt+q`. Модификаторы: `ctrl`, `alt`, `shift`, `cmd`/`super` (синонимы → `SUPER`), `mod`. Имена клавиш — таблица из `KeyInput::parse_combo` (`src/app/keyboard/key_input.rs:50`): разбор токена клавиши выносится оттуда в общую функцию и используется обоими, без копии. Порядок модификаторов в строке не важен, повтор — ошибка.
* `mod` разрешается при разборе: `SUPER` на macOS, `CTRL` на остальных. В `Chord` хранится уже разрешённый модификатор, поэтому сравнение платформенно-независимо.
* Сериализация: если сочетание содержит основной модификатор платформы (`CTRL` вне macOS, `SUPER` на macOS), он пишется как `mod`; второй — явно (`ctrl` на macOS). Порядок записи: `mod`, `ctrl`, `cmd`, `alt`, `shift`, клавиша.
* Отображение: Linux/Windows — `Ctrl+Shift+F`, `Alt+Q`, `F5`; macOS — символы `⌃⌥⇧⌘` в порядке Apple и клавиша: `⌘⇧F`, `⌥Q`.

### 2.3 Допустимость сочетания

`validate(chord) -> Result<(), ChordError>`:
* `Reserved` — сочетание из `RESERVED` (§3.4);
* `NeedsModifier` — клавиша — буква, цифра или знак, а модификаторов нет или только `SHIFT` (Q14);
* голый Escape — всегда `Reserved` (Escape отменяет запись; с модификатором допустим);
* без модификатора допустимы только F1–F12, Insert, Pause.

### 2.4 `Keymap`

```rust
pub struct KeymapOverrides { raw: BTreeMap<String, serde_json::Value> }  // как в config.json, включая ошибочные записи
pub struct Keymap {
    chords: Vec<SmallVec<[Chord; 3]>>,   // индекс — Command
    labels: Vec<String>,                 // отображение первого сочетания или «не назначено»
    skipped: Vec<SkippedEntry>,          // для красной строки и лога
}
impl Keymap {
    pub fn build(overrides: &KeymapOverrides) -> Keymap;
    pub fn hit(&self, cmd: Command, chord: Chord) -> bool;   // linear по ≤3 элементам
    pub fn chords(&self, cmd: Command) -> &[Chord];
    pub fn label(&self, cmd: Command) -> &str;
    pub fn owner_of(&self, chord: Chord, ctx: KeyContext) -> Option<Command>;  // для конфликтов, вне горячего пути
}
```

* `KeymapOverrides` — единственный владелец пользовательских данных; `Keymap` всегда строится из него целиком (`build`) после каждого изменения. Поле `App.keymap` и `App.keymap_overrides` меняются только методом `App::set_keymap_overrides(new)`, который пересобирает `Keymap`, сохраняет конфиг и обновляет подписи (§6) — одна точка фиксации (AGENTS.md §5 Design).
* `hit` не аллоцирует и не хеширует; `Chord` события вычисляется один раз на нажатие (§3.1).

## 3. Диспатч (O1)

### 3.1 Сочетание события

`Chord::from_event(physical_key, modifiers) -> Option<Chord>` в начале обработки нажатия (только `Pressed`; повтор обрабатывается так же, как сейчас обрабатывает каждая ветка). Для `PhysicalKey::Unidentified` — `None`, ни одна команда не срабатывает.

Windows AltGr: если платформа Windows и нажаты Ctrl и Alt, а событие несёт текст (`text_input_modifiers_allowed` и непустой `text`), `from_event` возвращает `None`: это ввод символа. Без текста Ctrl+Alt+X — обычное сочетание. Логика берётся из существующего `primary_shortcut_for_platform` (`src/platform.rs:341-352`); правило про текст — новое, потому что Ctrl+Alt-сочетания теперь можно назначать (Q2).

### 3.2 Ветки остаются на месте

Ветки в `src/app/keyboard/main_keys.rs`, `src/app/keyboard/editor_keys.rs`, `src/app/keyboard.rs` и панельных файлах (PDF, изображение, дерево файлов, БД, markdown, API) остаются в том же порядке и с теми же условиями контекста (фокус, режим, активная вкладка). Меняется только проверка клавиши и модификаторов:

```rust
PhysicalKey::Code(KeyCode::KeyS) if ctrl => { ... }          // было
_ if self.keymap.hit(Command::Save, chord) => { ... }         // стало
```

Ветки, где одна команда сейчас ловится двумя проверками (redo — `Ctrl+Y` и `Ctrl+Shift+Z`), сводятся в одну `hit` с двумя умолчаниями. Одно сочетание, означающее разные команды в разных контекстах (например, `Ctrl+C` в логе установщика и в редакторе), — разные `Command` с разными `KeyContext`.

Инвариант, проверяемый unit-тестом (`include_str!` диспатчеров, §8.2): у каждой `Command` с непустым `defaults` ровно одно место `hit(Command::X` в коде; у каждой `Command` без умолчаний и вне §4.3 — тоже одно.

### 3.3 Точное совпадение модификаторов (Q20)

`hit` сравнивает модификаторы точно. Сегодняшние нестрогие ветки (`KeyS if ctrl` срабатывает и на `Ctrl+Shift+S`, `F1` — и на `Shift+F1`; инвентаризация нашла такое почти во всех местах) теряют случайные варианты. Намеренные варианты становятся явными умолчаниями. Это единственное разрешённое отличие от «как сейчас»; инвентаризация (§8.1) помечает каждый нестрогий вариант, который покрыт тестом или документацией, — он переносится в умолчания.

### 3.4 Резерв

`RESERVED` — список фиксированных сочетаний из §1 (без модификаторов, с `SHIFT`, с word-модификатором платформы и `SHIFT`+word). Записать их нельзя (§5.3), в конфиге они пропускаются (§4.2). Причина: эти ветки стоят раньше команд и съели бы нажатие.

### 3.5 Терминал (Q10)

Терминал в фокусе по-прежнему забирает свои сочетания — порядок и условия веток не меняются. Keymap влияет только на команды приложения. Если пользователь назначает глобальной команде сочетание, которое терминал в фокусе перехватывает (`Ctrl+A`–`Ctrl+Z`, `Primary+V`, `Ctrl+F` — список §8.1), вкладка показывает предупреждение «в фокусе терминала перехватывается терминалом», запись не блокируется.

## 4. Новые команды

### 4.1 Диспатч

`App::run_command(cmd: Command) -> CommandOutcome` в `src/app/keyboard/commands.rs`; `enum CommandOutcome { Done, Unavailable(&'static str) }`. Вызывает те же методы, что обработчики `UiId` соответствующих кнопок (`src/app/ui_handlers/ui_git.rs`, `ui_lsp.rs`, `ui_database.rs`, `ui_editor.rs`, `api_client_app_click_methods.rs`), без копий логики; где обработчик кнопки принимает индекс (`GitPush(workspace_idx)`, `LspServerRestart(idx)`), команда берёт индекс активного репозитория / сервера активного документа, а общий код выносится в метод, который зовут оба.

Цикл по командам §4.3 — в `main_keys.rs` на глобальном этапе: после веток, которые забирает терминал в фокусе, и до диспатча редактора. Первая команда, чей `hit` сработал, выполняется.

### 4.2 Неприменимая команда (Q22)

`Unavailable(причина)` — клавиша забрана, в статус-строку пишется причина («Git: нет активного репозитория», «Нет открытой таблицы БД»). Исключение: в фокусе терминал и сочетание из списка перехватов терминала (§3.5) — клавиша уходит терминалу, сообщения нет.

## 5. Вкладка Settings «Горячие клавиши» (Q9)

### 5.1 Размещение

Седьмая вкладка сайдбара после «Базы данных» (`src/render_view/settings_ui.rs:519`, массив `tabs`). Рендер — новый файл `src/render_view/settings_keymap_ui.rs` (`settings_ui.rs` уже 1520 строк). Состояние — `KeymapSettingsState` (фильтр — существующий однострочный ввод, прокрутка, `recording: Option<Recording>`, `pending_conflict: Option<Conflict>`, текст подсказки записи) с собственными методами; клики — новые `UiId` через `src/app/ui_handlers/ui_settings.rs`.

### 5.2 Раскладка

Сверху вниз: красная строка «пропущено N записей keymap» (если `skipped` не пуст; подробности — в логе); поле фильтра и кнопка «Сбросить все»; список по `KeyContext` с заголовками групп. Строка команды: подпись, мелкий id, чипы сочетаний с «×», кнопка «+», «↺» (только у команд, у которых есть ключ в `KeymapOverrides`). Изменённые команды выделены акцентом, конфликтующие (§7) — пометкой «конфликт».

Фильтр — подстрока без учёта регистра по подписи, id и отображаемым сочетаниям обеих форм (`ctrl+s` найдёт «Сохранить»). Строки — от округлённых базовых линий через существующие хелперы строк/прокрутки Settings; хитбоксы — только через `UiId`.

### 5.3 Запись

* «+» → чип «Нажмите сочетание…», `recording = Some`. Пока запись идёт, следующее нажатие перехватывается до любого диспатча (в начале `handle_main_keyboard_input_inner`, рядом со startup-gate); нажатия одних модификаторов игнорируются.
* Голый Escape или клик мимо чипа — отмена записи.
* `validate` → `Reserved` — подсказка «зарезервировано», `NeedsModifier` — «нужен Ctrl/Alt/⌘»; запись продолжается.
* Сочетание уже у этой команды — запись заканчивается без изменений.
* `owner_of(chord, ctx)` находит команду X в том же контексте или в `Global` (а для глобальной команды — в любом контексте) → строка «Занято: X. Переназначить?» с [Да] / [Нет] (Q5). «Да» снимает сочетание с X и добавляет текущей команде одним `set_keymap_overrides`; «Нет» — отмена.
* Сочетание из перехватов терминала у глобальной команды — предупреждение §3.5, сочетание добавляется.
* «×» снимает сочетание (последнее снятое даёт `[]`). «↺» удаляет ключ команды. «Сбросить все» — через существующий диалог подтверждения, затем удаляет все ключи с известными id (пропущенные записи остаются, §4 persist).

## 6. Подписи в UI (Q12)

Тексты с сочетаниями строятся из keymap: `src/render_view/ui.rs:1471` («Ctrl+O — открыть файл»), `src/render_view/ide_panels/ide_panel_project_search_renderer.rs:519` («Ctrl+Enter …»), справка `FAQ_TEXT` (`src/app/app_bootstrap.rs:10`) и подписи в Settings, которые найдёт инвентаризация. `FAQ_TEXT` становится шаблоном: строки команд содержат `{cmd:<id>}`, подставляется `keymap.label`; строки фиксированных клавиш (`Ctrl + ←/→`, `Ctrl + Bksp`) остаются литералами. Готовые строки хранятся и пересобираются в `set_keymap_overrides`; в кадре — без `format!` и аллокаций. Команда без сочетания показывается как «не назначено».

## 7. Сохранение и ошибки (Q8, Q17)

* `Config.keymap: KeymapOverrides` (`src/state_persistence.rs:19`). Разбор — в `parse_config_content` из `serde_json::Value`: отсутствие поля или не-объект — пустые overrides и одна строка в лог. Запись — существующим атомарным `save_config`.
* Содержимое: только отличия. Нет ключа — умолчание; `[]` — сочетаний нет; список — замена умолчаний. Если после изменения набор равен умолчанию (без учёта порядка), ключ удаляется.
* Ошибки при `build`, каждая — строка в лог и элемент `skipped`:
  * неизвестный id или значение не массив строк — запись целиком пропущена;
  * неразборчивое сочетание, `validate`-ошибка — пропущено только оно, остальные сочетания записи действуют.
* Пропущенные записи сохраняются нетронутыми (Q23): `KeymapOverrides.raw` хранит исходные значения, сохранение из UI меняет только ключи известных команд. Красная строка остаётся, пока пользователь не исправит файл.
* Конфликт из ручной правки (одно сочетание у двух команд в одном контексте или с `Global`) — обе привязки действуют, срабатывает та, чья ветка раньше; во вкладке обе строки помечены «конфликт». Через UI конфликт создать нельзя (§5.3).

## 8. Тесты

### 8.1 Инвентаризация и характеризация — первая задача, до изменения диспатча

Инвентаризация на текущем коде: для каждого места диспатча — `file:line`, клавиша, проверка модификаторов, контекст, действие, предлагаемые `id` и `KeyContext`, нестрогие варианты и где они покрыты тестом или документацией; перечень перехватов терминала. Результат — `docs/hotkeys-inventory.md`, из него собирается `COMMANDS`.

Характеризация: табличный headless-тест на текущем коде — для каждой команды по умолчанию нажать сочетание в её контексте и проверить эффект через `dump`; команды без эффекта, видимого через `dump`, перечислены в тесте явно с причиной. После перевода на keymap тест проходит без правок.

### 8.2 Инвариант «умолчания не меняются»

Характеризационный тест §8.1 и существующие headless-тесты сочетаний (`ui_tests_editor.rs::headless_editor_save_undo_redo_shortcuts`, `ui_tests_editor_shortcuts.rs`, `ui_tests_keyboard_panels.rs`, `ui_tests_markdown*`, `ui_tests_pdf.rs`) проходят без правок. Исключение — тест, который проверяет нестрогий вариант, не перенесённый в умолчания по §3.3: такая правка теста перечисляется в отчёте задачи с причиной.

### 8.3 Unit (`src/keymap.rs`)

* разбор/сериализация/отображение, `mod` для Linux, Windows, macOS (через `PlatformKind`, как `primary_shortcut_for_platform`), повтор модификатора, пустой токен;
* точное совпадение модификаторов; AltGr Windows (Ctrl+Alt с текстом — `None`, без текста — сочетание);
* `validate`: голая буква, `shift+a`, голый Escape, `RESERVED`, `f5`, `insert`;
* `build`: неизвестный id, не-массив, не-строка в массиве, мусорное сочетание, `[]`, лишние поля, равенство умолчанию удаляет ключ; пропущенные записи переживают сохранение;
* `COMMANDS`: id уникальны, `Command as usize` = индекс, умолчания разбираются и проходят `validate`, нет конфликтов умолчаний в одном контексте и с `Global` (кроме перечисленных в инвентаризации существующих, если есть);
* ровно одно место `hit(Command::X` на команду (§3.2).

### 8.4 Headless-сценарии

* переназначение через `config.json`: новое сочетание работает, старое — нет; `[]` снимает;
* вкладка: добавить сочетание, конфликт с «Да» и «Нет», отмена Escape, отказ на зарезервированное, «×», «↺», «Сбросить все» с подтверждением, фильтр по подписи и по сочетанию, красная строка пропущенных;
* команда §4.3 без условия — сообщение в статус-строке; с условием — эффект;
* терминал в фокусе забирает своё сочетание, назначенное глобальной команде.

## 9. Риски

* R1. Пропущенная ветка при переводе на keymap — команда перестаёт работать или остаётся непереназначаемой. Страховка — §8.1 и unit «ровно одно место».
* R2. Изменение порядка веток при правке `match` (ветка с `hit` вместо паттерна по клавише проверяется в той же позиции, но guard-only ветки в `match physical_key` должны идти до `_`-ветки по умолчанию). Страховка — характеризация.
* R3. Горячий путь: `hit` вызывается десятками веток на нажатие — линейный проход по ≤3 сочетаниям, без аллокаций; это нажатие, не кадр.
